# CIOC V0.12 — 双诊断策略交叉检查与有限再生

本轮把 V0.11 的诊断策略 D 拆为两个职责不同的程序：DR（监测角色 O/G/V/M）与 DP（监测协议 PV/PI）。两者均可损坏和替换；存活的一方通过有限的正/反样本检查另一方，再以不完整的指令片段合成替代程序。**不是赛博生命或严格组织闭合的证明。**

## 运行

Python 3.10+，仅标准库。**需要保留同级目录** `experiments/v0.10/cioc.py` 和 `experiments/v0.11/cioc.py`：

```bash
cd experiments/v0.12
python -m unittest -v
python run.py
```

`run.py` 生成 `results/experiments.json`。`test_output.txt` 为同一实现的测试记录。

## 机制及边界

- 两个程序的规范形分别是 `DR=(SCAN_ROLE, REPORT)` 和 `DP=(SCAN_PROTOCOL, REPORT)`，其中 `REPORT_ALT` 在有限检查中可替换 `REPORT`。
- 每个诊断程序的初始可用片段仅公开首条指令，不包含完整替代代码。
- 对方可使用正样本（坏组件应报警）和负样本（好组件不应报警）测试；程序缺失或行为错误会被检查出。
- 若 DR/DP 检测到角色/协议功能错误，则隔离后沿用 V0.10 的有限维修能力。
- 仍然由**宿主**提供沙箱指令语义、正反样本、定额扣除、测试结果的判定以及统一安装流程。代码中 `_peer_checks` 也存在对等程序健康性宿主预检，故**尚不能声称诊断决策完全内生**。
- 存活的 O/G/V/M 对诊断程序再生属于预设依赖。O 依旧单点故障；DR+DP 同时损坏无法恢复。

## 结果

13 项测试通过；18 个场景运行完毕。DR、DP 单独缺失/错误均可在限定条件下恢复；联合失效、坏对等组件、片段缺失、低预算、关闭恢复权限均失败。源码不同但行为等价的诊断程序未被误报；顺序 DR 后 DP 损坏可连续恢复。
