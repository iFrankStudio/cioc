# CIOC V0.10 — 可损伤委托协议与有限协议再生

研究对象从 V0.9 的 O/G/V/M 维护角色延伸到两个**生命体内部程序资产**：`PV`（验证器缺失时的委托验证协议）与 `PI`（修改器缺失时的委托安装协议）。这不是完整的组织闭合证明。

## 本轮新机制

- 委托协议从宿主 `if` 路径变为可损伤、可替换的三条指令程序：`PV`、`PI`。
- 通用 `protocol_probe` 解释器执行程序，组合条件与输出证书/安装授权。协议程序本身位于 `World.protocols`，能被删除。
- 存活角色各自持有协议**首位或末位**的局部指令片段；未知中间指令由 G 通过有限枚举生成、V 用有限行为样例验收、M 提交。
- 可重新合成源码不同但在既定有限行为探针中有效的 `NEG_M_ALT`、`PERMIT_G_ALT`。
- 原协议恢复后，再损坏对应角色 V/M；其恢复过程会**执行恢复后的协议程序**，而不是只通过孤立的单元测试。
- 同时损坏协议及其依赖角色、丢失片段或预算不足均被保留为失败对照。

## 复现

Python 3.10+，不需要第三方依赖：

```bash
cd experiments/v0.10
python -m unittest -v
python run.py
```

`run.py` 生成 `results/experiments.json`；已保存 `test_output.txt` 与 `实验报告.md`。

## 主要限制

1. **宿主仍负责统一 tick/搜索调度、有限行为契约的裁判、通用指令解释、原子写入和算力预算**。只有 PV/PI 的*协议指令序列*变为可损伤的内部程序，不代表整个委托协议栈或验证基础已内生。
2. 角色 O 仍不可内部再生；PV+V、PI+M 同时损坏仍无法恢复。组织依赖的关键故障切集未消除。
3. 程序信息片段、操作语言与测试刺激均由实验者预设；程序等价仅限有限探针。
4. 本实验只检测将协议设为 `None` 的显式损伤；**非空但错误的协议程序不会被自动诊断并替换**。这一失败已列入测试。
5. 不具备开放式演化、自然形成的资源循环或赛博生命诞生的证据。
