# CIOC V0.3 实验报告

**主题：无完整模板的维护算法再生与受限程序合成**  
**性质：确定性模拟、可复现的工程基准；非生命存在性证明**

## 1. 研究问题

V0.2 依靠完整目标备份恢复算法，本轮检验：当目标组件丢失其可执行程序、维护者不读取目标实现模板时，内部组织能否使用有限基础操作与行为反馈生成可工作的替代程序？对照条件能否区分内部合成和外部修复？

## 2. 模型与方法

世界内有 A、B、C 三组件，维护许可环 A→B→C→A。功能规范分别为 A(x)=x+2、B(x)=2x+1、C(x)=x²−1。目标程序被删除后，内部维护者枚举长度 1—3 的指令序列。对每个候选使用训练集检验，通过后使用不重叠的保留集检验，最后世界在原子提交前再次验证功能。每次候选检验和提交均占用预算，所有关键事件进入日志。

这里“无完整模板”准确地指内部合成器不访问工作程序原文或完好程序备份；研究者规定的输入输出任务目标依然存在，世界也拥有验收接口，不能称为无先验知识生成。

## 3. 实际结果

| 场景 | 组织可行 | 内部提交 | 外部修复 | 候选检查 | 剩余预算 |
|---|---|---:|---:|---:|---:|
| 连续内部再生 | 是 | 2 | 0 | 47 | 547 |
| 禁用搜索器 | 否 | 0 | 0 | 0 | 600 |
| 外部修复基线 | 是 | 0 | 1 | 0 | 595 |
| 禁用维护来源 | 否 | 0 | 0 | 0 | 600 |
| 预算过低 | 否 | 0 | 0 | 15 | 0 |
| 移除关键指令 | 否 | 0 | 0 | 155 | 445 |
| 搜索器自身受损 | 否 | 0 | 0 | 0 | 600 |
| 恢复 A | 是 | 1 | 0 | 8 | 589 |

合成出的替代程序：B 为 `DOUBLE → INC`，C 为 `SQUARE → DEC`。它们均不同于初始程序：B 为 `INC → DOUBLE → DEC`，C 为 `DEC → INC → SQUARE → DEC`。

执行 `python -m unittest -v`，**14/14** 项测试通过。

## 4. 推论边界

* **支持**：预先给定有限指令集及目标功能时，内部维护者可以在限定算力内产生与原程序不同、通过独立测试的替代算法；内部与外部修复在事件日志中可区分。
* **不支持**：程序完全自主地定义功能、拥有全域数学正确性、维护搜索器本身、实现组织闭合、证明具有生命。
* **重要对照**：移除 `SQUARE` 后，候选集合只含仿射类一元变换（及其组合），无法表达 C 的二次函数；禁用维护来源和禁用搜索器亦使恢复失败。
* **行为验证局限**：有限个输入输出样本不能对任意整数程序证明语义等价；当前指令集极小，保留集只是防止部分过拟合，不是形式证明。

## 5. 与 CIOC 理论的关系

本轮只验证**结构/算法的可替代性**和**维持行为的内部来源**这两个局部能力。CIOC 的组织个体性要求进一步估计因果维护超边、调节器自身的闭合、资源获取下的长期可行性，以及非任意的个体边界。下一轮建议让搜索、验证与修复调节器均成为可损伤、可相互维护的程序结构，再进行真正的反事实闭合实验。
