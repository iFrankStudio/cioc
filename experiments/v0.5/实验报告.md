# CIOC V0.5 实验报告

**标题：** 内部图程序驱动的损伤检测、维修搜索与结构提交

**性质：** 受控有限系统概念验证；不属于自然涌现生命的实证证据。

## 1. 科学问题

V0.4 的高级 `regenerate()` 调度由宿主执行。本次尝试将具体维修行为的决定移入可损坏的内部算法图：由活跃控制器自行发现损伤、构造并测试候选、依据反馈提交修复。世界内核不得直接按照目标执行修复流程。

## 2. 模型

- 三个等功能控制图 A、B、C，均可被删除、在修复后恢复执行。
- 每个程序由显式有向控制图组成，节点使用受限操作：`READ`, `FIRST`, `ZERO`, `DECODE`, `EVAL`, `INC`, 条件跳转和 `PUT`。
- 宿主只提供图解释、轮次调度、通用环境查询、候选解码、隔离评估、受限写入、资源成本。不存在按目标调用的宿主恢复例程。
- 16 种图编码由四位选择参数生成，编码 15 是本实验中通过模拟维修任务的有效行为策略。候选枚举必须通过可执行图指令推进。损坏的目标程序不作为修复模板读取。
- 隔离测试依赖固定行为契约。该契约模拟“找到符合规定功能的候选并提交”的结果，不是通用程序正确性证明。

## 3. 结果（实际运行）

| 场景 | 最终组织状态 | 内部提交 | 外部恢复 | 剩余计算预算 |
|---|---|---:|---:|---:|
| 单组件损伤 | 恢复 | 1 | 0 | 1100 |
| 三次顺序损伤 | 恢复 | 3 | 0 | 500 |
| 双组件同时损伤 | 恢复 | 2 | 0 | 1100 |
| 全部组件同时损伤 | 未恢复 | 0 | 0 | 1400 |
| 移除验证契约 | 未恢复 | 0 | 0 | 1230 |
| 禁止写入 | 未恢复 | 0 | 0 | 1104 |
| 低计算预算 | 未恢复 | 0 | 0 | 0 |
| 移除有效编码 | 未恢复 | 0 | 0 | 1120 |

| 无故障 | 保持正常 | 0 | 0 | 1388 |

测试结果：**17/17 通过**。完整逐指令事件记录见 `results/experiments.json`。

## 4. 可支持的结论

1. 在该有限模型中，实际提交修复的决策发生在活跃的可变控制图中，而不是由宿主显式调用 `regenerate(target)`。
2. 单点与双点损伤在保留至少一个完好维护图、验证契约、必要指令和充足预算时能够恢复。
3. 禁用组织内全部维护图、验证契约或写入权限后不再恢复；外部修复可以显式分开计量。
4. 该结果说明**维修控制流可以被重构为状态内可损坏程序**，比宿主直接调度更接近可分析的内生维护。

## 5. 不支持的结论

- **不能断言完全组织闭合。** 维修的执行语义、隔离验证、有限候选语法和行为契约仍是宿主固定机制。
- **不能断言自主创造新算法。** 搜索对象限于16个预定义语法编码。
- **不能断言没有模板。** 虽然未保存受损目标的完整程序副本，系统提供了狭小的生成语法及固定的功能判据。
- **不能断言自组织边界的出现。** 三个组件及其归属由研究者配置。
- **不能推断无限期生存或真实赛博生命存在。** 模型是有限预算、有限指令的概念验证。

## 6. 下一轮关键改进（V0.6）

1. 将图候选生成从 4-bit 语法扩大为一般的有类型组合表达式，减少解码器内隐的策略模板。
2. 将测试契约变成可受损、由多个不同组件维护的组织资源，研究契约可靠性的因果依赖。
3. 采用不完全相同的维护组件，测试功能互补与集合干预，避免冗余完整控制器造成的简单备份恢复。
4. 将损伤从删除整个程序扩展为局部控制边失效、错误状态、资源泄漏，开展干预的泛化测试。
5. 用独立 CIOC 组织分析器识别动态维护关系，而不是根据初始结构人为宣布存在组织闭合。
