# CIOC V0.9 — 验证器与修改器的有限内部再生

这是对 V0.8 的独立机制实验：研究互补维护组织中原本的关键单点故障 **V（验证）** 和 **M（修改）** 是否能够借助剩余角色的有限、分布式能力恢复。**本实验并不证明真正数字生命、自组织或严格的组织闭合。**

## 运行

Python 3.10+，仅依赖标准库：

```bash
cd experiments/v0.9
python -m unittest -v
python run.py
```

第二条命令会生成 `results/experiments.json`；`test_output.txt` 记录对应测试输出。

## 设计变化

- O：故障识别、维修请求；G：有限搜索与候选提交。
- 当 V 缺失：O 与 M 分别执行正向和负向行为探针，联合替代验证阶段。任一授权关闭时，V 无法恢复。
- 当 M 缺失：经 V 检验的候选由具有 `DELEGATE` 能力的 G 在受限世界接口中安装。禁止该权限时，M 无法恢复。
- 当 G 缺失：继承 V0.8 的 O 备用搜索路径，仍由 V/M 完成验证与安装。
- 每份程序片段只公开指令位置，不保存完整目标程序；搜索未知中间指令。`CERTIFY_ALT`、`COMMIT_ALT` 和 `PROPOSE_ALT` 与原指令在**有限探针**中产生相同可观察作用。
- 分离内部维修与外部恢复的事件和计数；设置预算、丢失片段、取消委托能力、联合故障等负对照。
- 连续损伤测试验证：重建 V/M/G 后，其替代指令仍可参与下一轮维护。

## 当前界限

1. **O 仍是单点故障。** 同时失去 V+M 或 G+V 也会使再生失败，不能据此宣称完整组织闭合。
2. 宿主内核仍提供指令解释、有限候选枚举、行为测试原语、角色级权限判定和原子安装。尤其 `validate` 和 `install` 中的委托路径是**实验者预设协议**，不是自发形成的维修组织。
3. 分布式片段、正反探针期望和初始角色也是人工配置的。行为等价只在两个布尔刺激上成立，不保证开放环境等价或安全。
4. 修复能力的形成和功能目标的来源均未实现开放式发现；不得把此实验宣传为生命诞生或从零生成完整算法。

请阅读 `实验报告.md` 对失败条件的进一步解释。
