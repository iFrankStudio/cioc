# CIOC 最小基准实验（Proof of Concept v0.1）

本项目用于**检验因果干预式组织闭合模型的识别规则**，不代表已经创造出生命，也不能证明组织闭合的充分性。

## 快速执行

需要 Python 3.10+，只使用标准库。

```bash
python -m unittest -v test_benchmark.py
python run.py
```

输出 `results/experiments.json` 和 `results/detected_cutsets.csv`。`run.py` 采用固定种子与指定的 4 个逻辑事件观察窗，结果可复现。

## 四类微型组织

| 案例 | 组件及机制 | 期望识别结果 |
|---|---|---|
| `call_cycle` | A→B→C→A 只是调用，无修复 | 零维护证据 |
| `internal_closure` | C 修复 A，A 修复 B，B 修复 C；A 还修复 D | A/B/C 相互维护候选，D 是被维护外围 |
| `external_repair` | 外部 F 修复 A/B/C/D | 外部依赖，不构成内部维护闭合 |
| `redundant_maintenance` | A 或 B 均能修复 C；C 修复 A/B | 单次禁用 A 或 B 对 C 无效，联合禁用才揭示维护依赖 |

组件 E 为非维护日志节点。A/B/C 为核心候选，D 是外围功能，F 为外部控制器。所有案例用相同的执行和观测接口。

## 干预及识别方法

先将目标组件设置为损坏状态，再在其他条件相同的多个回合中比较：不禁用组件 vs 禁用候选维护源（最多 2 个）。观察窗 4 个事件。指标为目标能否恢复。

`loss = baseline_recovery - intervention_recovery`。结果达到阈值 0.25，则报告**最小失效切集**。特别注意：`{A,B}` 是失效切集时，不应解释为 A、B 必须协同修复；它也可能表示两个可替换的维护渠道。

每次事件消耗计算预算 1，内部修复再消耗 2。外部控制器修复从其独立预算扣除 2。配额不足则无法修复，说明拓扑闭合本身不保证资源可行性。

## 严格局限

1. 修复策略由实验者预先指定，只验证识别方法，**不验证涌现、自组织或开放式演化**。
2. 组件是预先分割的；未解决组件粒度和非唯一边界问题。
3. 探针通过干预发现的是维持相关性和因果失效切集，不证明直接因果超边，也不能单独证明约束再生产意义上的组织闭合。
4. 故障是单节点损坏，干预是临时禁用；没有覆盖同时损坏、依赖失败传播或结构重编程。
5. 观察窗有限，随机环境只以执行成功率近似。报告的 Wilson 区间仅量化二项抽样不确定性。
6. `classify` 内的三节点循环判据仅适用于本小型基准，不能当做通用生命分类器。
7. 当前 `core_viable` 为简化指标，不处理高维资源可行域、组织再生产、跨事件身份连续性。

## 结果解读补充

分析器同时返回 `three_node_internal_maintenance_cycle_detected` 和 `strongly_connected_internal_support_candidate`。前者只针对 A/B/C 三节点简单环，后者为用最小失效切集构成的潜在支持图的强连通候选。冗余维护场景中前者为 `false`，后者为 `true`，这是有意保留的区分；它不说明强连通图是组织闭合的充分条件。详见《实验报告.md》。
