# CIOC V0.2 — 动态组织与维护机制再生实验

这是在 CIOC V0.1 因果修复基准之后的独立增量实验。**研究用途，不构成生命存在的证据。**

## 运行

需要 Python 3.10+，无第三方依赖。

```bash
python -m unittest discover -v
python run.py
```

输出位于 `results/experiments.json`，包含候选算法搜索、干预和提交事件。

## 模型

- 三个组件 A、B、C 构成环形维护权限：A 可修复 B，B 可修复 C，C 可修复 A。
- 每个组件拥有自己的可执行维修程序、构造片段和受控备份。维修程序本身可以被删除或污染。
- 内部策略遍历局部指令片段组成候选修复流程，交给世界的受限语义执行器验证；验证后才提交修改。验证/搜索每次扣减 2 单位计算预算。
- 世界负责预算、权限和原子提交，不自动寻找修复方案；`external_restore` 是显式的外部维修对照。
- 运行后的 revision、事件日志、内部或外部维修来源均可追踪。

## 实验条件

| 场景 | 目标 |
| --- | --- |
| internal_regeneration | B 受损→A 修复 B→C 受损→恢复后的 B 修复 C |
| fixed | 禁止内部算法组合，检验固定组织无法修复 |
| external | 由外部修复服务恢复，避免误报内部自主性 |
| maintenance_cut | 禁用唯一可用的 B 修复提供者 A |
| insufficient_resources | 计算预算不足，无法完成有效候选搜索 |
| broken_blueprint | 唯一备份损坏，内部搜索无法恢复有效程序 |

## 关键限制

1. 它恢复的是**已知正确程序的功能**，不是发明全新算法。备份包含目标程序，候选搜索只重排 3 条固定操作。
2. 目标权限、结构和局部维护策略均为实验者预先规定。即使修复通过内部组件实现，也不等于已验证自主生命。
3. `World.verify_candidate` 使用实验内固定的语义真值（规范程序），为受控基准服务；未知算法语义尚未解决。
4. `OrganismPolicy` 是独立定义的驻留控制器，但其策略代码本身不能修改或再生，因此尚未达到完整组织约束的闭合。
5. 目前没有随机试验、群体统计、开放式环境、组织边界自动推断，不能声称得到一般化结论。
6. 禁用组件 A 是实验干预，不代表已从生命本体中删除 A。实验只证明条件性修复依赖。

## 下一步

V0.3 应将候选搜索策略本身表示为可损坏、可修改的受限算法节点，并设计跨任务功能验证、不携带完整目标备份的恢复实验、变更后的持续适应性评估。因果识别与组织边界判断仍由 V0.1 分析器的后续升级承担。
