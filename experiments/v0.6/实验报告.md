# CIOC V0.6 实验报告

**主题：互补型维护角色、受损功能契约与受限程序合成**

## 1. 研究问题

V0.5 的三个维护控制器具备高度重叠的维修能力，容易将冗余备份的效果误认为组织协作。V0.6 将任务损伤恢复拆为 O 检测、G 搜索、V 验证、M 提交四个互补角色，考察单角色消融是否造成明确的因果影响。功能契约也成为可受损的内部信息对象。

## 2. 设计

- 正常任务：整数函数 `f(x)=2x+1`，任务程序失效时通过枚举 1～3 条基本指令重新合成。
- 合成指令：`INC`（加一）、`DOUBLE`（乘二）、`SQUARE`（平方）、`DEC`（减一）。至多 `4+16+64=84` 个候选。
- 训练契约：`(-3,-5)`、`(0,1)`、`(1,3)`、`(5,11)`。
- 留出检查：`-9,-2,4,11,15,24,31`，用于实验者独立审查；并未向角色公开目标函数公式。
- 契约信息被拆为两片 XOR 数据：O、V 分别保存；M 保存摘要、负责收集与重组。单份片段缺失时无法重建契约。
- 调度器只调用各角色的 Python 策略并维护消息，修复业务逻辑分散在四种角色内；这个事实限制了“内生性”的强度。

## 3. 执行方法

```bash
python -m unittest -v
python run.py
```

测试通过：**16/16**。共执行 **13 个实验场景**，记录完整事件至 `results/experiments.json`。

## 4. 结果摘要

| 场景 | 任务恢复 | 契约恢复 | 内部任务/契约恢复次数 | 合成候选数 |
|---|---|---|---|---:|
| 任务算法损坏 | 是 | 是 | 1 / 0 | 9 |
| 功能契约损坏 | 是（未损坏） | 是 | 0 / 1 | 0 |
| 任务与契约同时损坏 | 是 | 是 | 1 / 1 | 9 |
| 禁用 O | 否 | 是 | 0 / 0 | 0 |
| 禁用 G | 否 | 是 | 0 / 0 | 0 |
| 禁用 V | 否 | 是 | 0 / 0 | 1 |
| 禁用 M | 否 | 是 | 0 / 0 | 84 |
| 契约 O 片段丢失 | 是（未损坏） | 否 | 0 / 0 | 0 |

成功合成的任务程序为 `DOUBLE → INC`，通过全部 7 个留出样本检查。不能由此推出一般程序推理或开放式创新能力。

## 5. 解释

**支持的结论**：在这个可控有限系统中，任务恢复需要多个互补维护角色共同提供功能。对角色实施禁用干预，会导致可预测的恢复失败；当契约数据丢失时，两个互补片段可在校验后合并以恢复契约。

**不支持的结论**：

- 不能宣称组织能再生 O/G/V/M；它们的行为策略仍是预设 Python 方法，受损后无法自我恢复。
- 不能将 XOR 两片恢复解释为新知识涌现；它是已有信息的冗余存储和重新组装。
- 不能证明系统在开放世界中具备生命组织的稳定持续性。
- 对照是受控的玩具模型，不是对 CIOC 数学闭合条件的完整验证。

## 6. 相比 V0.5 的真实进展与退步

**进展**：引入功能互补、角色单点消融、契约数据受损与双片段重组，明确暴露非冗余维护链上的依赖关系。

**退步**：V0.5 使用可修改的图控制程序，V0.6 的四角色策略则在 Python 实现层固定。这是为了隔离“互补性”变量而做的实验设计取舍。二者应在后续版本结合，而不是将 V0.6 解释为对 V0.5 的所有维度都更先进。

## 7. 下一阶段

V0.7 优先将互补角色移植回可修改的受限图 VM，并研究损伤角色本身如何由其他能力组合恢复。其次对不同目标函数、不同约束分布和多种联合干预开展重复实验，构造有因果证据的维护超图。
