# CIOC 研究检查点：V0.13—V0.16

**结果性质：**四个独立或继承的有限 Python 原型。不是单调升级的一个统一数字生命体，更不是数字生命已出现的证据。所有结果都限定在相应的世界模型、初始程序、资源定价与检测规则下。

| 版本 | 主要研究维度 | 正向证据 | 核心未解问题 |
|---|---|---|---|
| V0.13 | 对抗/冲突诊断 | 单个反向见证者下的有限多数判定 | 宿主 canary、串谋、多数失效 |
| V0.14 | 资源、复制与变异 | 切换资源时有变异种群的相对存续 | 受限词汇、无自身维护 |
| V0.15 | 代价内生维护 | 高损伤环境下修复的净效用、局部自适应重配 | 控制器单点故障、宿主修复原语 |
| V0.16 | 生态 + 局部互修 | 双控制器单点修复及修复后延续代谢 | 预置功能冗余、双故障切集 |

## 当前最接近目标的候选

综合原生资源竞争、可遗传变异与内部功能维持的**V0.16**。但它不比 V0.12 在所有因果闭合维度上更强（V0.12 研究多角色互补诊断，V0.16 重点转向个体生态中的控制器冗余）。禁止用线性版本编号推断单调科学进步。

## 实验停止条件

当提升仅依靠增加预先设计的备份角色、扩大宿主专用维修函数或增加有限测试样本，而不能减少外置生命功能时，应停止叠加版本。本轮满足该停止条件。可转入 CL-0 工程阶段。

## CL-0 下一步需达成的可证伪里程碑

1. Rust 实现确定性世界、资源守恒、最小指令解释器与独立事件日志；冻结内核可提供的功能白名单，不能直接有 `repair_role()` 这类专项生命函数。
2. CIL 图程序可更改自身和互补组件的控制流；内存、执行步骤和存储全部收取明确资源费用。
3. 不同初始种子下出现维护依赖；用删除、替换、资源阻断、共享故障和外部代修区分因果来源。
4. 将干预样本和反证结果长期持久化，用结构新颖度、稳健性、谱系多样性等指标检验是否存在持续创新，而非只统计活了多久。
5. 将宿主 oracle 的比例、硬编码功能种类、最小切集、不可恢复故障比例作为“离组织闭合仍有多远”的反向指标；缺少进展不应继续宣布更高版本成功。

**结论：**有了较可靠的有限实验工具和失败证据；距真正开放式数字生命仍有核心理论与工程障碍。
