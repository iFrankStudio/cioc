# CL-1 Research Handoff — From a Validated World to Falsifiable Organization Experiments

**Status: planning framework only. No CL-1 hypothesis has been experimentally confirmed or CL-1 stage accepted.**

## What is inherited (without reinterpretation)

CL-0 is accepted **as infrastructure**: deterministic Rust/CIL world, bounded abstract compute/storage, generic graph construction, process execution, object read permissions, external action provenance, SQLite exact replay, Python analysis and a Vue read-only observer. The [accepted evidence](CL-0-acceptance.md) includes 24 seeded initial worlds × four matched conditions with 96 exact replays, not 96 independent proofs of self-organization.

The historical CIOC V0.1–V0.16 models and their built-in repair/controller assumptions remain a separate archive. Their successes must **not** be promoted to native-world discoveries.

## Scientific target

Explore whether bounded executable information structures can spontaneously develop a **causally interdependent, persistent, internally maintained organization** without the host selecting preferred structures or implementing a maintenance/fitness oracle. The world need not look like biological life, and “organism” is not an initial world object type.

Separate at least four hypotheses:
1. **Persistence:** active arrangements remain functionally coherent for a specified number of opportunities after initial external construction ceases.
2. **Internal causal dependence:** removing or degrading one internally produced component materially changes another component's persistence, beyond activity-matched sham interventions.
3. **Self-maintenance under resource constraints:** recovery, if any, is initiated by world CIL activity using accounted internal/external supplies, and is absent under compute-matched inert and scrambled-code controls.
4. **Accumulated endogenous novelty:** new effective instruction-graph structures arise from internal operations and persist across independently measured windows, rather than being counted simply because externally seeded programs differ.

These are possible research questions, not empirical findings. Each needs an **operational definition**, threshold and failure condition registered *before* running candidate experiments.

## Proposed minimal independent protocol (to preregister before execution)

| Requirement | Recommended minimum design |
| --- | --- |
| Independent trials | Multiple distinct seeds and independent world initializations; report exact count and seed derivation |
| Matched control | Common serialized initial state with no intervention, sham intervention, and targeted disruption |
| Resource controls | No-credit, no-new-storage, restricted external compute supply and budget-matched random-code conditions |
| Provenance | Label every source of programs, instructions, compute resources and external intervention |
| Outcomes | Predefined graph persistence, causal impact of ablations, internal code-change provenance and resource debt |
| Negative capability | Report total null/failed/trapped/inert worlds and unreachable intervention offsets, not just survivors |
| Robustness | Repeat at different budgets/seeds and avoid selecting outcomes based on favorable visible traces |
| Reproduction | Persist initial and pre-action hashes, exact source commit, parameter settings, SQLite artifacts and replay verdicts |

Do not use a reward, `FITNESS`, `REPAIR`, `REPRODUCE` or hidden host validator to “encourage” success. Any sampling or candidate-selection protocol implemented **outside** CIL must be declared as investigator intervention and excluded from endogenous novelty claims.

## Causal validity safeguards

- **Negative result is a result:** a completely inert world, a failed code synthesis attempt, or an inaccessible object must remain in the denominator.
- **Causal necessity is not life:** a graph node required for a process to execute is not by itself evidence of organizational closure; establish bidirectional or distributed dependency at an appropriate independently defined level.
- **No free restarts:** process launch and restoration need credit and storage attribution; a host-provided restart or replenishment cannot count as internally initiated recovery.
- **No post-hoc life metrics:** a long trace, increasing storage occupation, many graph nodes or multiple child processes are not sufficient criteria.
- **Artifact isolation:** the analyst and Vue console cannot mutate the world; rerun from archived baselines to reproduce interventions.
- **Observer limitations:** a deterministic same-seed replay proves repeatability, not independent discovery. Favor fresh seeds and condition-level replication.

## Technical gaps worth addressing in CL-1

The current world still has abstract rather than physical-unit costing, public shared data cells, limited graph/object ownership delegation and no modeled persistent-versus-working memory tiers. Long-running experiments also need explicit caps on generated states and independent audit of snapshot formats; neither a richer visualizer nor biological metaphor should precede causal validity.

## Stage acceptance rule

Do **not** mark CL-1 complete just because new experiments run, programs clone, or some outcomes look organized. Publish a preregistered, independently repeatable causal result with null controls, provenance and uncertainty; if no such evidence emerges, record **CL-1 investigation inconclusive / negative**, not “life created.”

Current handoff remains a protocol proposal only; formal preregistration and research execution must be separately committed with a dated revision before inspecting CL-1 outcomes.
