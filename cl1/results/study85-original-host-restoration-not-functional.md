# CL-1 Study85 — original effective lesion's failed host-restoration control

**Status: retrospective source-pinned independent verification; zero new ecological worlds.** [Protocol](../studies/85-registered-retrospective-failed-host-code-restoration.md) was explicitly filed after outcomes. [Original Study84 corpus](https://github.com/iFrankStudio/cioc/actions/runs/43594558556/artifacts/14113728079), SHA `85087980474e3885f41576f3ae50f3c925edba83`; retrospective Study85 [successful CI43594991537](https://github.com/iFrankStudio/cioc/actions/runs/43594991537).

Study85 recomputed all **1,536** original full native-world event runs, **27,648** exact SHA256 epoch snapshots and original `E=10, L=1, R=0` fixed outcome gates before classifying the previously known single exposed-and-effectively-lesioned seed **5,700,098**. Both source3 and source8 worlds had their exact original pre-fork PC8 outgoing code edge restored by an explicitly **External** `PatchEdge` intervention at postfork epoch4. In BOTH arms, **no subsequent native source output was recorded** through the late recovery window; neither passed the strict two-window function-restoration gate. The original host repair does not magically reactivate a stopped process, rewind the PC, refill the actor's own compute or reconstruct register state.

**Interpretation:** An externally restored *byte-identical damaged edge* is not necessarily an externally restored **function**. The recovery assay has a missing effective positive control on the only L case, preventing the null `R=0/128` from establishing that native code re-editing could never recover a damaged function. The experiment remains evidence of one effective functional lesion and an unvalidated recovery test, **not a demonstration of irreparable endogenous code**. A subsequent read-only source-PC/credits/stopped chronology is needed to distinguish irreversibly trapped actors from credit-gated or behaviorally diverted actors. No retrospective seed may be included as independent novel ecology.

**Next-study design constraint:** freeze an **early, recoverable, nonfatal** intervention window with a demonstrated external functional positive control before sampling any new random CIL genotypes; do not tune original Study84 seed, lesion or recovery windows post outcome. CL-1 remains **OPEN**.

## Verified supplementary full native-PC/credit chronology, not an added cohort

A focused re-execution of the same read-only original Stage84 auditor (no new worlds) succeeded in [CI run43595235138](https://github.com/iFrankStudio/cioc/actions/runs/43595235138). At actual affected seed **5,700,098**, in BOTH source3/8 host-restore arms the actor was **not stopped** before host restoration, had **72 local credits**, and occupied **PC5** at the end of postfork epoch3. The exact External PatchEdge **did** restore PC8.next from damaged3 to original9 at global epoch10; after another 12 charged native attempts in epoch4 the actor was still at **PC5** with **60 credits**, no native source output. Over all subsequent postfork epochs4..17 there were **72 charged native attempts, zero subsequent source reads and zero native writes**, with no native trapped/halted event. In the untouched/sham comparator, the same seed remained active around PC8 and performed **14 late source reads and 14 late source writes per source arm**.

Thus the failure is **not due to permanent Trapped/Halted state or the host failing to restore executable code**. The lesion diverted the surviving actor into a live but output-inaccessible PC5 control-flow attractor: repairing a code edge at PC8 is ineffective while the actor never revisits PC8. A causally informative positive-control test must keep the damaged node re-encounterable (for example a lesion setting PC8's next edge to **PC8 itself**, with post-lesion external restoration and real mutation-disabled controls) rather than making arbitrary functional edges inaccessible. This attractor is identified **retrospectively from Study84 data**; any revised target is a distinct, explicitly preregistered follow-up, never an alteration of Study84's original endpoint.
