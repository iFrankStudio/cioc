# CL-1 structural capacity bound — why fixed-28-node one-actor mutation ecologies cannot produce open-ended evolution

**Type: source-level mathematical/architectural argument, NOT another ecological experiment.** Applicable specifically to the **frozen Study82→Study94 eight-way random-grammar family** (not the whole Rust/CIL VM and not every earlier CL-1 experiment). This result does not depend on the numerical outcome of Study94 and makes **zero** claims about the presence or absence of an organism in arbitrary digital worlds.

## Exact premises visible in committed CIL generator and VM

1. `code_for_seed` constructs exactly **28 executable nodes** in a single `Process::new(1, nodes, 64)`: three researcher-defined initial `Const` nodes that initialize R1=8, R2=7, R3=9; 24 random native CIL nodes at PCs3..26; and a terminal `Halt` at PC27. The code is generated once before any native ecological execution. Concrete source: `cl0/crates/lab/src/bin/cl1-study94.rs`, inherited unchanged from `cl1-study82`/Study86/88/91.
2. The *only* eight possible stochastic opcodes are `Read`, `Write`, `Add`, `Sub`, `Const`, `Branch`, `DrawCompute` and `PatchNext`. **No** `GraphNew`, `GraphEncode`, `GraphCopyNode`, `GraphLaunch`, `GraphSetNext`, `CloneNode`, `GraphReplace` or `PatchConst` appears in the native random genotype. The *world VM itself* has other generic graph opcodes, but the probability of invoking them from these existing CIL programs is identically zero, not merely small.
3. In this family, every native operand that writes a register only changes **R0** after the first three Consts. Therefore R1 remains **exactly 8** across successful native execution; R2 and R3 remain7 and9. Every stochastic `PatchNext {node:1, target:0, next:...}` targets the fixed executable node **PC8**, using R0 only as the *new next-edge value*. A successful native `PatchNext` can change **only** `code.nodes[8].next`; it changes no opcode tag, data operand, other edge, process count or graph object.
4. This single-actor native grammar has **no native process spawning, no native code allocation, no gene copying, and no inheritance events**. All postfork `Intervention::PatchEdge`, public compute pool input, and source-cell initialization are explicitly **External** and cannot be counted as endogenous structural evolution.

## Consequence: bound on attainable executable-genome structures

For a fixed initial genotype, all native-executable code nodes other than PC8 remain invariant. If PC8 has one patchable `next` field, that `next` can point only to one of the **28 existing nodes** (0..27); therefore at most **28 distinct native executable graphs** can occur under *all possible* internal execution histories of this one starting genotype. If PC8 is a `Branch`, it lacks a single patchable `next` edge and every native PatchNext on PC8 traps rather than editing; in that case there is exactly **one** native executable graph. There is no path to increasing code size, discovering new opcodes, propagating innovations through descendants, or diversifying interacting organizations. Even unbounded repetition of the same in-place edit does not increase this finite structural bound.

This does **not** prove that one-edge edits can never causally restore an injured function: the scripted Stage80, Stage90 and Stage93 fixtures demonstrate exactly such a possibility under different hand-authored code. It **does** prove that merely scaling the same native eight-way graph grammar to more random seeds, longer finite epochs or richer external compute supply cannot by itself establish **open-ended executable-genome evolution, functional heredity, or multi-process mutually maintained closure**. These predicates are excluded by the chosen native opcode support, not merely unseen by chance.

The source-based upper bound should shape the next scientific program after the ongoing frozen Study94 finishes: retain Study94's registered narrow causal functional-restoration question unchanged, then independently pre-register a **qualitatively distinct** ecology permitting native generative code construction, process/graph ownership, imperfect copy/inheritance and resource competition under generic CIL substrate physics, with strong host vs actor origin and offspring function controls. This is not a proposal to add a special organism or goal-directed repair/selection primitive. It is a warning against calling a single edit-edge lottery an open-ended evolution study.

**Scientific classification:** logical capacity limit of a restricted experimental genotype language. Not a computational impossibility proof for general CIL; not another stochastic trial; not evidence for or against the origin of life. CL-1 remains OPEN.
