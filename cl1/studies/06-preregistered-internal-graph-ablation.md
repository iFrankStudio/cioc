# CL-1 Study 06 — preregistered causal ablation of internally constructed graph objects

**Registration date:** 2026-11-13, **before** implementing Study-06 code or looking at Study-06 outcomes. Prior Studies 01–05 were known. Fresh independent seed inputs are **1160000 through 1160127 inclusive**, with no selection or reruns from earlier cohorts.

## Aim and limits
Test whether graph objects **constructed internally by general CIL graph operations** become causally relevant to ongoing computation, as distinct from externally authored initial process code. The experiment asks a necessary question about the organization of native information. **Even a positive effect of object deletion would not demonstrate maintenance, repair, organism identity or life.**

## Frozen generator and prefork state
- **128** seed-worlds. Copy the Study-04 generic 16-node random CIL generator *without changing instruction choices*, three process IDs 1..3, 28 initial credits/process, 32 shared cells, max 32 code nodes/process, total 160 strict abstract storage units.
- At creation, the investigator externally calls `SetComputePool{credits:64}` once, with its `Origin::External` event recorded. This is a predeclared environmental resource, not internally created energy.
- Each world runs up to **32 CIL attempts** as a *shared pretreatment history*. If the world exhausts earlier, it remains in the cohort.
- Deterministic eligible target rule **before any matched treatment**: select the **lowest existing graph-object handle whose node list is nonempty**. It must have been generated by CIL execution because the world was initialized with no graph objects. If none exists, record `no-target` and select invalid sentinel handle **0**; **do not drop that world or change its seed**.
- Record the prefork state and its provenance as the **identical initial snapshot for all conditions**. The handle and its owner are fixed for that seed before the experiment forks. They are investigator-read data used only for lesion selection, never a CIL fitness instruction.

## Four matched conditions per seed, 20 independent external epochs × 8 CIL attempts/epoch
1. `control`: no intervention.
2. `sham-drop`: externally attempt `DropGraph{graph:0}` at epoch 0; this is a logged rejected intervention and must leave all subsequent *simulated state* equal to control (excluding external log/tick).
3. `target-drop`: externally `DropGraph{graph:selected_id}` at epoch 0; if no target, the same failed sentinel intervention as the sham. An actual deletion **must** be logged as external and refund object storage units.
4. `disable-owner`: externally `Disable{process:owner}` at epoch 0; if no target, attempt to disable impossible process ID 9999 (logged rejection). This is a positive perturbation control for removing the agent that generated the object; no special host repairs.
5. `zero-credit`: set all process credits to zero at epoch 0; environment compute pool may remain nonzero but cannot automatically revive the processes.

**5 × 128 = 640** matched runs, each with **20 saved epoch state snapshots**, identical initial hash within a seed, and exact SQLite replay.

## Prespecified endpoints
- `eligible_target`: yes/no for each of 128 prefork worlds.
- `drop_exposed`: target exists, successful external deletion logged at epoch 0. A world without a target remains in the 128-world denominator.
- `indirect_process_impact`: for exposed worlds, compare final process states (all process IDs, code, registers, credits, stop flags) between `control` and `target-drop`, **excluding the target object map, environment pool, events and ticks**. This prevents simply counting the deleted object as causal evidence.
- `nonowner_process_impact`: same comparison excluding owner process (if target exists); shows at most a propagation/scheduling effect, **not** reciprocal functional closure.
- `postdrop_object_creation`: after targeted deletion, a new graph with handle absent from the common prefork object set and nonempty nodes exists, owned by the original target owner. This is only **structural creation** and must never be called replacement, repair or organizational maintenance without an independent functional test.
- `sham_equivalence`: every control-vs-sham final simulated state, excluding logs/ticks, must match. Any violation invalidates the experiment.
- `no_credit_control`: zero CIL attempts in the zero-credit arm.
- For all outcomes, report numerator/128; also report numerator/eligible among exposure-eligible worlds but never imply a randomly selected eligible-only sample represents the entire seed distribution. Include a Wilson 95% confidence interval for 128 independent seed-worlds.

## Integrity, source and negative-results rule
All run states, all epoch snapshots, all external intervention results and their SHA-256 hashes must match exact replay. Every run remains under 160 storage units; any arithmetic violation invalidates full Study 06. Sources must be cited by commit hash and locked dependencies; 128 independent worlds, not 640 conditions, are the unit of replication.

A single process constructing or using an object can create one-way dependency, but is **not organizational closure**. To claim CL-1 complete would require preregistered **distributed bidirectional functional maintenance**, recovery after ablation without host-directed repair, stable multi-epoch organization and internal source tracing. This study does not test those properties and cannot on its own pass the positive CL-1 stage gate.
