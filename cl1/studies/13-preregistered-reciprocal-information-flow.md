# CL-1 Study 13 — preregistered reciprocal information-flow interruption

**Registration:** 2026-11-13, before Study-13 implementation, trial execution, or outcomes. Studies 01–12 are known. New independent seeds **1930000..1930095** (96). This is a deliberately null-capable **functional dependency probe**; even a successful bidirectional graph-copy cycle is **not** organizational closure, repair or cyberlife.

## Fixed world and initialization
Reuse the *exact 12-way randomized initial code generator* from Study 12, unchanged except fresh seeds. Three process IDs 1,2,3 each have 28 program nodes (first nine are investigator-authored symmetric graph creation, shared handle publication and read permission; following 18 are externally randomized general instructions; final Halt), 56 compute credits/process; strict world max32 shared cells, max40 nodes/process, total storage192, no external compute pool. LCG wraps u64 with multiplier 6364136223846793005, addend1442695040888963407, initial state = seed. Prefix requires **27 deterministic attempted instructions** before the common fork. All common snapshots must have nonempty graphs1,2,3, public handles 0,1,2, and read grants to predecessor. This is a researcher-built opportunity, not endogenous organization.

## Six matched conditions
For each exact common-prefork snapshot, make **six** separate, identically bounded branches, each running **16 independent external epochs × 12 CIL-instruction opportunities**:
1. `control`: no environmental intervention.
2. `sham-drop`: rejected external `DropGraph {graph:0}` at epoch0.
3. `drop-g1`: external `DropGraph {graph:1}` at epoch0.
4. `drop-g2`: external `DropGraph {graph:2}` at epoch0.
5. `drop-both`: two independent external drops, graph1 then graph2, at epoch0.
6. `zero-credit`: external `SetCredits{process:i,credits:0}` for every extant process at epoch0.

Thus **96 × 6 = 576 exact-replayed SQLite runs**, with **9,216 postepoch hash snapshots** and all failed/trapped/inert trials retained. Graph ablations and credits are explicitly external, never CIL repair or life properties. The host does not restore deleted graph references or create any replacement graphs.

## Independently declared information-processing function
Define a directed successful information edge **A→B** for each observer `GraphCopied {source_owner:A,target_owner:B}` event with `Origin::Internal(actor=B)`, A != B, and PC ≥9 occurring *after the common fork*. Ignore all `GraphTransferred` events for this marker. A read grant, failed/trapped copy, externally prewritten prefix or graph count change is **not** an edge.

Partition each 16-epoch run into two **nonoverlapping observation windows**, W1=epochs0–7 and W2=epochs8–15. In each window, a **bidirectional information-function candidate** exists iff there is an unordered pair (A,B), A != B, with at least one successful A→B and at least one successful B→A within that window. Aggregate by independent seed-world; never treat paired branches as independent replicates. This is an **observer-defined functional marker**, not a signal provided to agents, an adaptive objective or evidence of necessary regeneration.

## Registered endpoints, causal interpretation and stopping
- `bidirectional_w1`, `bidirectional_w2`, `bidirectional_both_windows` in untreated control: binary per seed. Report numerator/96, 95% Wilson intervals, edge/event totals and which owner pairs participated. Repeated events from one actor do not establish reciprocity.
- `single_target_causal_loss`: for worlds with untreated `bidirectional_w1=true`, graph1 or graph2 deletion causes absence of the *same pair's* bidirectional marker in W1, comparing matched sham control; if no untouched W1 function, report **unexposed**, not a life-property zero. Report exact counts with both 96 and exposed denominators.
- `joint_damage_increment`: graph1+2 deletion removes at least one bidirectional marker seen under control while neither single deletion does. This is a specificity probe, not proof of mutual maintenance.
- `postdamage_new_graph`: any successful postfork `GraphCreated` with handle not in the prefork object map, and subsequent internally charged node addition. Distinguish mere new headers from nonempty executable graph objects, and never call such growth repair.
- `late_reappearance_candidate`: a graph-deletion treatment has no bidirectional pair in W1, then a bidirectional pair in W2, **and** some successful `GraphCreated` plus `GraphNodeCopied` event occurred after the lesion. Label **candidate only**; later information flow does not imply restoration of the original function or an internally initiated recovery policy.
- `sham_equivalence`: control/sham simulated graph/process/shared cell/pool state at final observation is byte-identical, excluding event/tick metadata. Any difference invalidates entire study.
- `zero_credit`: exactly zero attempted internal instructions after fork.
- Every run must respect strict occupancy ≤192, exactly replay all external schedules and complete 16 snapshot hashes. Invalid or incomplete cohorts are **technical failures**, never data silently excluded.

## Scientific acceptance boundary
The original code, grants and three process identities are all externally specified. Mutual exchange might be caused by randomized static code and is not sufficient for self-maintenance; a late replacement object might have no function. Study 13 does **not** supply an external functional-restoration positive control or a causally identified self-generated recovery policy. Therefore **organizational closure and autonomous maintenance remain NOT EVALUABLE regardless of Study-13 counts**. A positive CL-1 stage verdict requires an independent subsequently preregistered test of multi-component functional repair (including external-restoration and sham controls) across multiple observation periods, with code/data ancestry traced beyond copies.
