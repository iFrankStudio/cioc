# CL-1 Study 41 — prospectively registered native CIL code-plasticity opportunity ecology

**Status: PROSPECTIVE registration before runner, independent audit and outcomes.** Studies38–40 show externally scheduled native W3 work; they do not test endogenous code changes. This is the first new independent study explicitly opening **generic self-code editing and graph launch** to stochastic native programs without prebuilding a repair or reproduction routine. No life-acceptance endpoint may be passed by code changes alone.

## Scientific question

Can seeded non-goal-directed CIL programs perform **native, internally attributed, resource-accounted modification of their own executable code**, continue to execute after those mutations and/or launch graph-derived child processes, under a bounded open world with a neutral external resource-access law? Does the observation require the new native operator opportunity rather than the earlier original grammar? No state/event may be counted as endogenous unless generated by an actual native instruction, not intervention or experimenter bootstrap.

Each process starts with 56 credits, prefork **27** native charged attempts, per-actor postfork 47 credits, world initial ambient pool48, world strict storage cap **256** (not 192) and per-process code-node cap **64** (not 40). Cell key bounds 32; 3 graphs' one-node scaffold, original owners/ACL.
- Continuation native choices: for each actor and node index9..35, draw `random(state)%20`, with **exact** mapping:
  0 `GraphCopyFrom(target=3,source=1,node=2,next)`,
  1 `GraphCopyNode(graph=3,source=2,dst=2,next)`,

  6 or7 `Write(address=0,value=3,next)`,
  8 `Const(dst=2,value=0,next)`,

  10 `ReturnCompute(amount=1,next)`,
  11 `GraphGrantRead(graph=3,reader=1,next)`,
  12 `CloneNode(dst=2,source=2,next)`,

## Registered paired arms (4 ×128=512 full native SQLite runs, 12,288 epoch hashes)

1. `ambient-general`: exactly above energy+neutral starter.
2. `ambient-only`: same ambient +8, **without** neutral starter.
3. `closed-general`: neutral starter but **without** any new ambient energy.
4. `zero-credit-ambient-general`: externally set all 3 process credits to zero at epoch0 (48 initial world-pool remains), then same ambient and neutral starter. This is explicitly externally ignited and is not an autonomy control.

The four arms start from the **same byte-identical common prefork world per seed** and differ only by registered external resource actions. No branch may edit initial code, inject a child, artificially repair a process, or alter mutation/launch instruction availability. Precompute state-dependent external actions by original-prediction simulation, run with existing `Laboratory::run_epochs`, byte-compare final worlds, and independently `verify_epoch_replay` every run.

## Frozen primary native mechanism endpoint

A world in `ambient-general` qualifies as `native_self_code_changed` if a **successful native internally attributed** `PatchNext`, `PatchConst` or `CloneNode` executes, and a byte-comparison of the actor's **executable code immediately before and after that specific native event** confirms its executable nodes changed. For provenance, the auditor must use per-epoch event and state histories; if only final snapshots are available, it must conservatively report `event-attributed code change` when the specific actor native operation plus final code comparison is sufficient, and **NOT EVALUABLE** for intermediate reverted changes. Do not infer a successful modification solely from an unvalidated `Executed` event. A successful native `GraphLaunch` with `GraphLaunched` provenance is a separately preregistered child-creation endpoint, not life or endogenous reproduction.

Report positive world counts /128 with Wilson 95% intervals and an exact first witness by seed, actor, event PC, target graph/code and epoch. The null is 0/128. No minimum success criterion is imposed. Even a positive native change is only a basic **code-plasticity capability**, not functional self-maintenance.

## Frozen secondary gates

- `successful_native_plastic_op`: any internally attributed successful PatchNext/PatchConst/CloneNode, regardless of net code change; successful events vs trapped attempts separated.
- `final_code_changed`: any initial actor's final executable code differs from its initial code; track normal native ancestry and possible reverting.
- `native_graph_constructed_or_modified`: internally sourced `GraphCreated`, `GraphNodeCopied`, `GraphEncoded`, `GraphLaunched` events; separate graphs from actual executable children.
- `mutated_actor_further_success`: at least one further successful native instruction by the **same actor after a qualifying patch/clone** (count within or after current epoch, explicit tick/order). A mutated code graph that immediately traps does not count.
- `native_child_continues`: successful native instruction by a child whose ID arose solely from a successful `GraphLaunched`, with provenance and credits spent, plus native attempts in at least two distinct epochs.
- `native_output_after_plasticity`: same actor successfully writes a shared cell after first native code change; distinguish whether output depends causally on changed instruction.
- W1/W2/W3 native attempts and successes with no same-epoch external starter; separate ambient external energy and host starter actions.
- Cap/failure distributions, traps, stopped actors, final compute inventory and strict one-credit-per-attempt conservation.

## Independent controls

- All 128 pre-registered seeds; no post-result selection, 4 arms each, full event/energy/timestamp provenance and 12,288 SHA256 snapshots.
- Python analysis must **independently** regenerate the initial seeded grammar and verify program nodes, resource totals, all epoch hashes, all planned ambient inputs/starter transfers, external provenance, native attempt ledger and strict caps; repeat initial/final code diff and code-opcode event attribution, separate graph mutation vs executable-code change.
- A tiny synthetic calibration for native `PatchNext` code change and failed/trapped mutation plus one host-only intervention must demonstrate sensitivity and reject false positives.
- No claims of hereditary self-reproduction, fitness, repair, organism creation or open-ended evolution from a child launch or patch. A stronger causal maintenance claim requires separate **prospective** self-initiated damage repair, lesion-sham, source ablation and no-host-rescue controls under preserved code ancestry.

## Interpretation

The experiment deliberately broadens **opportunities**, not success. A positive observation justifies later natural-selection-free tests of functional continuity and endogenous self-restoration; a null quantifies the feasibility bottleneck of stochastic executable plasticity. The world still has external ambient compute and external starter opportunities, neither generated by CIL. **CL-1 remains OPEN.**
