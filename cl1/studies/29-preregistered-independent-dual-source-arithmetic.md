# CL-1 Study 29 — preregistered independent two-code-source arithmetic dependency

**Registered 2026-11-13 before implementation, seed execution or outcome inspection.** Studies 27–28 are already known: two independent worlds demonstrated graph2 tag-dependent output address relocation; none demonstrated a graph1 **read-mediated** second component. This is a new independent ecological generator experiment, not a retrospective rescore of those two cases.

## Falsifiable question

Can **randomly continued CIL programs** use two independently owned graph-code sources, then combine their tags through the *ordinary native Add instruction* into an externally observable write-address function that is causally sensitive to **each component separately and both jointly**?

This is **not** a search for self-maintenance. The prefork programs, 9-node creation/permission scaffold, CIL instruction grammar, graph1 owner1 and graph2 owner2, source code replacement and substrate credits are authored by the investigator. Random continuation and actual source read/output effects are generated by normal CIL execution; observing them cannot establish spontaneous design.

## Frozen new ecology and unbiased instruction draws

- Exactly **256 independent seed-worlds `2,400,000..2,400,255`**, disjoint from every prior random cohort; same 3-process, externally seeded initial 9-instruction scaffold and prefork 27 charged attempts as Study27, strict `cells=32, maxnodes=40, total_storage=192`, 56 starting credits/process and 47 residual credits/process after prefork. Three original one-node graphs with owners 1–3 and the same fixed circular reader permissions.
- Each process receives **18 randomized continuation instructions, indices 9..26**, followed by a normal `Halt`. Use the **unchanged** 64-bit LCG from Study27, draw **one `random(state) % 12` choice for every node** (54 draws/world) and use the following public fixed *single-node* mapping. All forward `next=index+1`, except `Branch.nonzero=index-2` and `Branch.zero=index+1`:
  0. `GraphCopyFrom {target:3,source:1,node:2}`
  1. `GraphCopyNode {graph:3,source:2,dst:2}`
  2. `GraphSetConst {graph:3,node:2,value:0}`
  3. `GraphReadTag {dst:0,graph:3,node:2}` (reads own graph1 for actor1)
  4. `GraphReadTag {dst:2,graph:1,node:2}` (reads previously authorized foreign graph2 for actor1)
  5. `Add {dst:0,lhs:0,rhs:2}`
  6–7. `Write {address:0,value:3}`
  8. `Const {dst:2,value:0}`
  9. `Branch {test:1,nonzero:index-2,zero:next}`
  10. `GraphNew {dst:3,next}`
  11. `GraphGrantRead {graph:3,reader:1}`
- No instruction sequence is preinserted to guarantee dual read, Add, write, repair or reproduction. These are primitive operators with fixed probabilities and native resource costs. Do not adapt probabilities, choose favorable seeds, append more instructions or restart trapped programs after outcome inspection.

## Seven paired interventions and exposure

Exactly **7 branches per seed**: `control`; rejected `sham` DropGraph(0); `mutate-g1` (external DropGraph1 + PutGraph1 with node0 changed to Halt, tag19, original owner/access); `mutate-g2` (same graph2); `mutate-both` (both in graph-ID order); `exact-original-g2` (externally drop/reinsert same exact graph2 object); `zero-credit` (SetCredits 1–3 to zero at epoch0). Identical source-prefork snapshots per seed. **8 epochs × 12 charged native attempts** each, total **1,792 paired runs and 14,336 hash-verified postepoch SQLite snapshots**. Early dual-input-function exposure only; the study does not test late repair.

## Strict preregistered dual-source endpoint

For a seed to qualify, **all four** matched arms `control`, `mutate-g1`, `mutate-g2`, `mutate-both` must exhibit **in epoch0, from native process1**, successful source-owned `GraphTagRead` events for **graph1 owner1** and **graph2 owner2** before **one successful `CellWritten`** to the registered address, with no ambiguous multiple successful writes to that address after the reads. The observed source tags must agree with the exact source edits, and the following output-address pattern must hold:

| Arm | Source graph1 tag | Source graph2 tag | Required native write address |
| --- | ---: | ---: | ---: |
| control | 11 | 11 | **22** |
| mutate-g1 | 19 | 11 | **30** |
| mutate-g2 | 11 | 19 | **30** |
| mutate-both | 19 | 19 | **38** |

The **numeric output value** must be identical across all four matched branches; it is not preselected. This is a high-specificity additive **two-component external source-code content sensitivity** pattern. Without actual successful reads of *both* source graphs by process1 and matching all four outputs, the seed is **not** a strict dual-source function witness. Report separately, all out of 256 worlds: successful own/foreign reads, same-actor dual-read-before-write opportunities, single-arm expected writes, fully paired endpoint, source1-only and source2-only discordances, synthetic positive-control performance and 95% Wilson intervals. The paired arms are not independent samples.

This strict event test alone is not proof that the **specific register values** remained live at the Write instruction: interpretation is an externally induced controlled mechanism, not full runtime register-level taint. Never claim that the organization is endogenously designed or self-maintaining.
