## Fixed entirely generic CIL fixture

A single human-authored parent actor with 35 existing executable CIL nodes, finite 96 initial local credits, in a strict bounded native world, has **no parent shared output Write** in its executed control path. It executes only existing VM instructions: `GraphNew`, five `GraphCopyNodeLocal`, four `GraphSetNext`, `GraphLaunch`, register Const setup, and Halt. The five source nodes at PCs30..34 are ordinary CIL source-code templates, not a special VM reproduction opcode. They correspond to ordinary Const-R2=7, Const-R3=9, Read(source cell key7), Write(output cell key9), Branch to Read, in that order. The parent creates a new owned graph, copies the five original CIL code nodes in their original order, edits the first four ordinary next edges to link the child graph; GraphCopyNodeLocal **generically relocates** the Branch target source32→child2. It launches the native child with a finite **24 credits transferred out of parent's existing balance**, with no external per-child starter or additional compute. The child must initialize its **own registers** by executing the copied Consts, perform successful native `CellRead(key7)` and native `CellWritten(key9, source_value)` repeatedly at child PC3 in **two separated portions of the original event stream** under separately initialized external sensor source values 3 and 8. Child origin must be `Internal(child_id)` and parent must never emit output `CellWritten(key9)`. Actual graph copy and GraphLaunch events must be internally attributed to parent1; object ownership/compute conservation fully audited.

## Frozen controls

- **Native local-address code-copy positive:** five `GraphCopyNodeLocal` operations; four exact ordinary `GraphSetNext`; 24 child credits; both source inputs; require repeated true native child Read→Write. Child's actual CIL code and edges, not a dummy wrapper, must be inspected.
- **Absolute stale-edge negative:** identical parent construction except the five `GraphCopyNodeLocal` become original `GraphCopyNode`. The moved Branch retains source target32 rather than child2; the child graph/launch should reject/trap or never produce a valid child Write. No manually repaired edges in this control.
- **Zero-child-credit negative:** local graph copy and edits succeed but native GraphLaunch grants 0 child credits; no source writes by child. Native VM cannot silently endow credits.

The source fixture is known to the investigator; success proves only that **current unchanged VM syntax is able to natively assemble and execute a self-initializing five-opcode source-dependent child with functional repeated output**. It does **not** demonstrate spontaneous child assembly, replication, inheritable adaptation, multi-component organizational closure or emergence of life. All six fixture worlds (3 modes×2 source values) add ZERO stochastic ecological samples; no claim of organism. Targeted one-test Rust CI, not historic study rerun.
