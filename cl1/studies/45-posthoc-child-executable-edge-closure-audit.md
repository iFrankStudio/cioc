## Diagnostics, already post-result

For each child with internally attributed native `GraphLaunched` event and unique child ID, inspect its entire graph-derived executable program **as preserved in the final snapshot** and classify:
1. All node edge targets are inside 0..(child executable node_count−1): `next` for ordinary opcodes, both `nonzero`/`zero` for Branch, no outgoing edge for Halt.
2. At least one structural stale/out-of-bounds edge (even if never executed).
3. Child native instruction success versus Trapped("invalid edge") or other trap, directly sourced from chronological internal child events.
4. Reachable stale edge: a failed child's observed `pc` actually addresses an opcode whose out-of-bounds edge explains an `invalid edge` trap. This must not be conflated with a different native error.
5. Child program node opcode repertoire, including any `Write`, `Read`, `GraphNew`, `GraphSetNext`, `GraphEncode`; distribution by program length, parent and graph object.
6. Native child `CellWritten` events with exact preceding launch and original code PC, separately from output functional heredity.
