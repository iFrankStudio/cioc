# CL-1B — Continuous individual evolution

**Status: ACTIVE — initial causal feasibility phase, not a life discovery (2026-11-15).** Replaces population reproduction as the *default* research emphasis. [CL-1A](../cl1a/README.md) remains an archived, paused research route; original historical material remains under `cl1/`.

## Thesis and nonrequirements

Study whether **one logically continuous native digital organization** can maintain activity, alter its own executable information, recover from harmful internal changes, and accumulate effective adaptation under bounded compute/storage and environmental perturbations.

Birth, copy/launch, genetic inheritance, populations, aging, externally specified life rewards, and an immutable 'essential core' are **not necessary acceptance requirements**. Individual continuity is an empirically tested organizational relation, not process-ID equality, byte equality, uptime, or an observer's subjective attribution.

An organism-level conclusion must not be inferred solely from self-modifying code, an automatic rollback instruction, increasing output, a better hand-designed algorithm, or survival of a selected subset.

## Rules of the world

- Keep the accepted CL-0 Rust/CIL VM and generic, resource-accounted graph/information/compute primitives. No host `LIFE`, `REPAIR`, `FITNESS`, `OPTIMIZE`, or dedicated rollback oracle.
- Host snapshots/replay are **observer/laboratory instrumentation** unless a native agent itself constructs, owns, accesses and pays for corresponding recoverable information. Host test-harness restoration does not count as native recovery.
- Allow native code changes via existing CIL operations, including `PatchNext`, `PatchConst`, graph edits and normal writes. Trace internal vs external origin and debit every attempted instruction.
- A candidate may consist of several coupled processes or graph objects **within one causal organization**; do not define separate processes as separate lives by fiat. Account for all component state and storage.
- Researcher-authored seed code, descriptor layouts, protected monitors, repair scripts, and chosen perturbations must be labeled external. They may be used as *positive engineering controls*, never scored as spontaneous invention.

## Necessary resource feasibility condition (B18 source-level audit)

Finite **instantaneous** compute/storage capacity is compatible with long-term life, but a permanently closed world with finite **total lifetime** compute inventory is not: native CIL instruction charges eventually exhaust that inventory. Before interpreting B2–B4 as *ongoing* self-maintenance, establish an identity-neutral, auditable world-side **resource flux** and show that the individual itself accesses it through charged native actions. Host-targeted top-ups, initial endowment and merely having unspent credits at the observation cutoff must not count as endogenous resource acquisition. See [B18](results/B18-finite-compute-source-audit.md). This is a necessary condition, not sufficient evidence of cyberlife.

## Research phases / acceptance gates

| Gate | Exact question | Required evidence | Forbidden inference |
| --- | --- | --- | --- |
| B0 substrate | Can one CIL actor change its **own running** code, with causal behavior and finite charges? | single-actor self-edit vs mutation-disabled sham, intact actor identity, event/provenance/credit checks | that an authored edit is self-improvement |
| B1 functional continuity | Does a changing actor retain an independently declared function across multiple nontrivial internal code transitions? | matched initial worlds, measured pre/post function and code hashes, traps and losses retained | that a persistent PID equals persistent life |
| B2 native recovery | After a harmful perturbation, can internal operations recover relevant function without laboratory restore? | damage/sham/disabled-repair/resource-ablated arms, native snapshot provenance and complete resource accounting | that a host replay is self-healing |
| B3 cumulative adaptation | Do retained native changes improve persistence or task performance on **unseen environmental conditions**? | prospective training/holdout split, randomized order, matched edit opportunity/compute and negative controls | that externally selected best-of-N equals endogenous selection |
| B4 endogenous organization | Do the organization and adaptation policy arise from world-local interactions rather than a scripted repair/reward apparatus? | preregistered causal component ablations, multi-window self-maintenance, non-scripted provenance, independent replication | that a single good trace establishes life |

These gates are **sequential scientific claims**, not mandatory complexity of initial software releases. Negative results count. Do not quietly relax criteria or discard failed worlds.

This is an **engineering demonstration**, not autonomous improvement.
- [B01 preregistration](studies/B01-multi-edit-functional-continuity.md) · [focused Rust test](../cl0/crates/world/tests/cl1b_b01_functional_continuity.rs): three function windows after two internally applied graph-edge changes; functional, suppressed, and explicitly damaging controls, five input cases. **Code committed; CI outcome not independently verified.** This is an authored positive/negative calibration, not evolved continuity.
- [B02 preregistration](studies/B02-native-repair-calibration.md) · [focused Rust test](../cl0/crates/world/tests/cl1b_b02_native_repair_calibration.rs): a single CIL actor reads back a damaged executable edge and restores it internally, compared against no-damage and mutation-disabled controls under 40 equal local opportunities. **Code committed; CI outcome not independently verified.** The safeguard was scripted by researchers and is not endogenous recovery.
- [B03a prospective protocol](studies/B03a-computed-self-variant.md) · [focused Rust test](../cl0/crates/world/tests/cl1b_b03a_computed_self_variant.rs): same-process native `ReadNext` + environment datum + arithmetic computes a self-code edit target, with transparent external delta and service-output/resource checks. **Not native trial-and-error or adaptation.**
- [B03b prospective protocol](studies/B03b-native-trial-feedback-selection.md) · [focused Rust test](../cl0/crates/world/tests/cl1b_b03b_trial_feedback.rs): a single CIL actor executes a trial, observes its result, and conditionally edits its future code path; matched patch-suppressed arm. This is a **human-authored decision policy**, not unscripted adaptive emergence.
- [B04 prospective checkpoint protocol](studies/B04-actor-owned-checkpoint-rollback.md) · [focused Rust test](../cl0/crates/world/tests/cl1b_b04_native_checkpoint_rollback.rs): one CIL actor writes an internally observed code edge to a storage-accounted cell, later uses that saved value to undo an external code-edge lesion. Damage, native-patch-disabled, checkpoint-corrupted, and no-damage controls; 20 deterministic worlds. **Only static path simulation checked; native CI not yet verified.** Checkpoint guard is researcher-authored.
- [B05 prospective protocol](studies/B05-reciprocal-monitors-throughput-paradox.md) · [native Rust test](../cl0/crates/world/tests/cl1b_b05_reciprocal_monitors.rs) · [independent simplified path audit](results/B05-static-path-audit.md): two **human-authored** monitors protect each other inside one process. In simplified path simulation, either single monitor lesion is repaired but double lesion bypasses both checks while **doubling raw service output (10 versus 5)** per 100 opportunities. The apparent throughput gain is a negative control for false life/fitness metrics, **not** scientific confirmation or Rust CI verification.
- [B06 preregistered hypothesis and discrepancy log](studies/B06-poisoned-checkpoint-self-damage.md) · [simplified path audit](results/B06-simplified-path-audit.md) · [B05/B06 shared Rust experiment](../cl0/crates/world/tests/cl1b_b05_reciprocal_monitors.rs): corrupt actor-written *reference cells* rather than executable code and test whether CIL repairs healthy code into a damaged state. Simplified path simulation refuted B06's original **two-edit** double-poison prediction: an erroneous A edit disables B first, causing **one edit only**. Both original prediction and post-registration correction are preserved; the new native test is *post hoc compatibility verification*, not a successful preregistered double-edit hypothesis. Full 25-world Rust CI results remain unverified.
- [B07 prospective safety–availability protocol](studies/B07-two-checkpoint-agreement-tradeoff.md) · [native Rust test](../cl0/crates/world/tests/cl1b_b07_checkpoint_agreement.rs) · [independent simplified audit](results/B07-independent-path-audit.md): CIL itself writes two copies of its observed own-code edge and a **researcher-authored** 2-of-2 agreement guard decides whether to alter the code. 35 conditions cover separate memory poisoning, correlated double poisoning, code damage, simultaneous code-and-memory damage and paid patch suppression. Simplified results show **safe refusal of a single poisoned copy at the cost of blocked recovery**, while correlated poison still drives self-damage. **CI not verified; no spontaneous self-maintenance claim.**
- [B08 pre-registered information-loss protocol](studies/B08-indistinguishable-histories.md) · [native Rust deterministic convergence test](../cl0/crates/world/tests/cl1b_b08_indistinguishable_histories.rs) · [independent path audit](results/B08-independent-information-boundary-audit.md): two different source-code/checkpoint histories are deliberately mapped to the **same present CIL-visible code, registers, cells and credits**, then future native event traces are compared for 80 attempts. A third arm with actor-written **original history preserved** can restore output. In the simplified model H_A and H_B stay identical and silent; retained-reference H_A repairs and outputs. **Not verified in native Rust CI; no autonomous adaptation claim.**
- [B09 preregistered new-evidence assay](studies/B09-evidence-after-history-loss.md) · [focused native Rust test](../cl0/crates/world/tests/cl1b_b09_trial_evidence.rs) · [full 25-condition independent path audit](results/B09-independent-trial-readback-audit.md): a single actor with **no saved code-edge checkpoint** reads a service output cell, compares against its source and computes an editable edge candidate from the **observed** edge minus one. Nonzero missing-output failures can be recovered using new native observations; **input0 aliases an absent output and stale matching output hides failure**, so no general diagnostic success is claimed. The candidate-generating rule and task are researcher-authored. Native CI remains unverified.
- [B10 preregistered native marker-freshness protocol](studies/B10-native-freshness-and-spoof.md) · [native Rust test](../cl0/crates/world/tests/cl1b_b10_freshness.rs) · [independent 25-condition path audit](results/B10-independent-freshness-audit.md): CIL resets its own marker cell before a trial, which distinguishes **absent output from valid zero and stale matching output**, but a deliberately timed external marker spoof after deletion still creates a false “healthy” judgment. This is an engineered scripted guard and a **threat-model-limited** result, not intrinsically trusted information or autonomous evolution. **Native CI unverified.**
- [B11 prospectively registered CIL serial candidate search](studies/B11-serial-native-candidate-search.md) · [native Rust test](../cl0/crates/world/tests/cl1b_b11_serial_candidate_search.rs) · [30-condition independent path audit](results/B11-serial-candidate-search-audit.md): a single native actor tests successive **self-generated code-edge candidates** (10→9→8→7) using fresh internal marker feedback and retains the first one that restores its pre-authored service criterion. Intermediate candidate next9 writes unintentionally to cell1, exposing real side effects and storage cost. **The policy and marker goal remain human-engineered.** No claim of endogenous evolution and **native CI still unverified**.
- [B12 prospective marker-versus-function falsifier](studies/B12-marker-function-divergence.md) · [native Rust controls](../cl0/crates/world/tests/cl1b_b12_marker_function_divergence.rs) · [independent path audit](results/B12-independent-marker-divergence-audit.md): with only one externally damaged code edge, a **fresh CIL-authored success marker** can repeatedly occur with **zero actual service writes**; conversely correct output can be misjudged as a failed trial and internal "repair" creates a low-value loop. In one simplified 80-instruction control, repair-enabled retains only 1 initial valid output versus 4 in patch-disabled. This reveals that B10/B11's fresh-marker proxy is **not a causal function witness under mutable code**. **Native Rust CI unverified; no spontaneous goal/fitness claim.**
- [B13 exhaustive preregistered evaluator robustness assay](studies/B13-exhaustive-marker-mutation-screen.md) · [source-parsed 1,805-world scanner](analysis/b13_edge_mutation_scan.mjs) · [native Rust differential test](../cl0/crates/world/tests/cl1b_b13_native_mutation_differential.rs) · [independent audit](results/B13-exhaustive-marker-mutation-audit.md) · [post-hoc decision-edge audit](results/B13b-decision-edge-audit.md): all one-next-edge mutations in B10's 20-node CIL program, rather than selected failures. Independent JS/Python interpreters agree on **66/1,805 false-acceptance worlds and 52 false-rejection worlds** (plus **336 traps**), with a marked input-zero effect. A stricter branch-consumption check found 95 mutant worlds where a marker read bypassed the decision branch, but the **66/52 world counts remained unchanged** in the simplified interpreter. This is an **observer-side robustness failure** of a researcher-authored evaluator; the Rust differential is **post hoc and remains unverified**. No native self-evolution, endogenous generation or researcher-selected winner is claimed.
- [B14 prospective executable search-policy modification](studies/B14-native-search-policy-mutation.md) · [native Rust test](../cl0/crates/world/tests/cl1b_b14_search_policy_mutation.rs) · [independent 30-world path audit](results/B14-policy-mutation-path-audit.md): the same CIL process uses paid `PatchConst` to modify its future candidate step literal **2→1** after feedback from a failed trial, then uses that actual altered opcode when proposing code changes via `PatchNext`. **Important counterexample:** the self-mutated policy is beneficial under lesion10 but slower under lesion11 than a locked-policy control; a mutable policy is not automatically a generally adaptive policy. Meta-search and reward criteria are investigator-authored; no emergent life claim.
- [B15 preregistered exhaustive cross-lesion evaluation](studies/B15-exhaustive-policy-generalization.md) · [350-world native differential](../cl0/crates/world/tests/cl1b_b15_policy_generalization.rs) · [source-parsed observer scanner](analysis/b15_policy_generalization.mjs) · [independent negative audit](results/B15-policy-generalization-audit.md) · [post-hoc unit/actual-policy-use correction](results/B15b-independent-unit-correction.md): a cost-matched **one-literal** source counterfactual tests B14's mutable candidate-step policy across all possible node6 successor edges, rather than only the favorable next10 lesion. Simplified results: **0/32 unique holdout edge types show improvement**, and two edge types show harm (repeated across five input labels). Only **31/160 input×edge conditions actually change and then execute the new policy literal**; within that narrower stratum: 0 wins, 10 losses, 21 ties. The earlier 0/10/150 count over 160 conditions remains descriptive, not 160 independent lesion samples. This is direct negative evidence against **generalized advantage of that authored rule**; no native Rust confirmation or spontaneous adaptation claim.
- [B16 preregistered actor-originated functional challenge](studies/B16-functional-challenge-and-forgery.md) · [native Rust test](../cl0/crates/world/tests/cl1b_b16_functional_challenge.rs) · [source-parsed 30-world interpreter](analysis/b16_functional_challenge_scan.mjs) · [independent audit](results/B16-independent-functional-challenge-audit.md): an actor creates a **nonzero challenge17**, deletes its actual output cell, executes the real payload-producing instruction and reads that output before deciding whether to self-edit. This detects a skipped service write and stale matching data even for **original input0**. Two negative controls still fool it: **mutated checker flow reads challenge input instead of payload**, and an externally forged response between CIL Delete and Read. This remains a researcher-authored diagnostic and has **no verified native Rust result**.
- [B17 prospectively registered exhaustive challenge-checker screen](studies/B17-exhaustive-challenge-mutation-screen.md) · [source-parsed observer scan](analysis/b17_challenge_mutation_scan.mjs) · [4,495-world native Rust differential](../cl0/crates/world/tests/cl1b_b17_native_challenge_mutation.rs) · [independent audit](results/B17-exhaustive-challenge-mutation-audit.md): legal one-next-edge mutations of the 32-node B16 actor expose **12 distinct false-acceptance** and **78 distinct false-rejection** code lesions, repeated across five input labels (60/390 affected simulated worlds). Only 2,625/4,495 simulated mutants reach the checker. Thus **direct nonzero functional readback is not a trusted oracle when its own graph can change**. The Rust native differential is committed but **not yet independently verified**; no autonomous evolution claimed.
- [B18 preregistered finite-compute necessary-condition analysis](studies/B18-finite-compute-no-perpetual-maintenance.md) · [native Rust closed-world accounting tests](../cl0/crates/world/tests/cl1b_b18_finite_compute_bound.rs) · [direct source-level conservation proof](results/B18-finite-compute-source-audit.md): every charged native CIL attempt consumes exactly one unit from **total actor credit + shared pool**, while Draw/Return/Transfer/GraphLaunch only move existing compute. With finite initial inventory and no externally supplied resource influx, **an individual cannot run indefinitely, regardless of self-repair sophistication**. A host `SetCredits` positive control is explicitly external, not an organism metabolism. This is a **physics-level necessary condition**, not emerging life, and its native regression remains unverified.
