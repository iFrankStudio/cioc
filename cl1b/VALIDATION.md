## Live SHA-pinned verification and archival channel

The [focused workflow](../.github/workflows/cl1b-focused.yml) now has two separated jobs: the Rust test job remains **read-only** and runs the selected native targets (**all** targets for full verification), accumulating failures rather than aborting the campaign on the first one; an independent *push-to-main-only* reporting job has narrowly scoped `contents:write` and writes a source-SHA/run-ID result record plus downloadable raw target logs to a separate **`cl1b-ci-evidence` branch**. This branch is not a trigger for the CL-1B focused workflow. No PR code receives a write-privileged reporting job.

**This route has now been observed completing successfully:** `cl1b-ci-evidence` contains the SHA-pinned full-run evidence for run 43723559666. For future commits, do not infer that a native run succeeded merely because the workflow exists. To retrieve evidence through the GitHub connector, search for branch `cl1b-ci-evidence`, then read `run-records/<main-SHA>-<run-ID>-<attempt>/result.txt` and `summary.txt` using `ref="cl1b-ci-evidence"`. Corroborate with the named per-target logs. If the evidence branch does not exist, it may indicate a queued workflow, a disabled Actions workflow, insufficient repository permissions or a job failure; report **UNVERIFIED** and inspect the Actions UI rather than guessing.

**CI false-green remediation:** On a routine changed-only run, a newly added `cl1b_*.rs` file **not present in the native test manifest** now fails rather than allowing a green workflow with zero executed targets. Full verification additionally checks that the selected target count is 24 and observer count is 10. These manifest counts must be updated deliberately whenever another native study is introduced.

## Scope-aware CI note

The native workflow now selects only the modified `cl1b_*.rs` test and known direct imported dependents for routine code changes; a CL-0 VM source/Cargo/workflow change or **manual workflow dispatch** forces the full suite. The `summary.txt` artifact records `scope`, `selected_native_targets` and changed paths. A successful **changed-only** run must never be represented as a passing B00–B21 campaign. The full source-pinned run 43723559666 was directly inspected; future changed-only passes certify only their selected targets.

## Native verification runbook

Use [the dedicated focused Actions workflow](../.github/workflows/cl1b-focused.yml), configured to run the explicitly named B00–B21 targets (all on a full-scope run, selected targets on a routine change). The job records the source commit `GITHUB_SHA`, workflow ID/attempt, Rust/Cargo toolchain versions, per-target exact `cargo test --locked -p cl0-world --test ... -- --nocapture` stdout/stderr and explicit PASS/FAIL lines.

1. Open **Actions → CL-1B focused native experiments** in GitHub and locate the run corresponding to the intended **source SHA** (a run being queued, skipped, cancelled or absent does **not** pass).
2. Require a completed **success** conclusion for that exact source revision, with all target lines PASS. A failure must remain archived, not silently reclassified. Note that the very first compilation may fail before later experiments are reached: absence of a result for later targets is neither pass nor fail.
3. Download the automatically uploaded `cl1b-native-<run ID>-<attempt>` artifact (uploaded **even on failed jobs**, if any file was produced). Preserve `provenance.txt`, `summary.txt`, all target logs and corresponding commit SHA in immutable experimental storage, where possible.
4. Check scientific content before promotion: human-authored seed programs, externally supplied interventions, resource charges, exact denominators, and no latent host repair oracle. A green Rust test is **engineering consistency**, not evidence of endogenous life.
5. If no run or artifact is visible, leave status **UNVERIFIED**. Do not infer GitHub execution from a successful commit or an empty commit-status response.

## Policy on future studies

**Do not launch an unbounded series of scripted guards and call it progress toward open-ended evolution.** Native evidence should be recovered before accepting mechanism claims. Subsequent studies must introduce a *scientifically discriminating* change such as agent-constructed competing hypotheses, within-individual policy revision based on paid native evidence, prospective holdouts or substantial falsification. Pre-register assumptions and keep all failures. Maintain CL-1A archive; avoid rerunning its hundreds of studies on each new CL-1B push.
