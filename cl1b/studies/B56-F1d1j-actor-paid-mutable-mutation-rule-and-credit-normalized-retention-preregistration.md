# CL-1B B56-F1d1j — actor-paid *mutable mutation rule* under strict resource physics (prospective)

**PROSPECTIVE ONLY — no F1d1j native source, no verified outcome and no current claim that a learning or mutation rule has evolved.** The previous original-source F1d1i full verification is [run44301654974](https://github.com/iFrankStudio/cioc/actions/runs/44301654974), 67/67 native tests and 58/58 observers, with 16,510 original paid instructions, 157 native CIL nodes and 16 total data addresses, peak174/300. F1d1i changed its **interpreted task program** following feedback, but its **mutation grammar A→C→B→A**, score2 acceptance threshold and fallback were themselves immutable researcher-written CIL source logic.

## Exact remaining explanatory gap

A fixed mutation cycle whose advancement is conditional on feedback is a genuine limited adaptive controller, but does **not** demonstrate an individual capable of revising *the way it generates future programs*. The next falsifier must separate:
1. **Task program**: the executable virtual bytecode currently being tested.
2. **Mutation rule descriptor**: persistent actor-owned data that changes which task program is proposed NEXT, with an actual native paid Write to the descriptor.
3. **Rule-choice evidence**: the actor's accumulated native paid evaluations and compute costs, showing why a rule descriptor changed before the next task program was generated.
4. **Candidate outcome**: novel or reused bytecode executes on held-out inputs in the SAME PID, with genuine charged costs and failures preserved.

A researcher-authored hardcoded branch that simply switches two predefined rule IDs on a single feedback bit is **not self-invention of a new mutation algorithm**. Even if it runs, label it only **within-PID modification of a researcher-given mutation-rule descriptor**.

## Frozen minimal rule concepts and negative controls (pre-exact manifest)

- Researcher-authored rule `R0` proposes candidate mode transitions `A→C→B→A` (prior F1d1i order). Researcher-authored rule `R1` proposes `A→B→C→A` (opposite order). Both can be data-encoded and edited by PID1, but no new primitive semantics are generated in this minimum study.
- Actor should initially execute the SAME 157-node-or-refactored founder on the same data program A and ordinary probe inputs. It must evaluate the **rule's behavior** using actual paid cost and feedback, then pay a Write changing the persistent rule descriptor before its next candidate proposal. The exact cost signal must be a genuine CIL-facing credit/inventory observation, or, if no such instruction exists, an actor-maintained *paid instruction count / explicit per-action cost surrogate* whose limitations are frozen BEFORE code. **Never let the test harness write a cost or winner into actor memory.**
- At least 2 held-out changes of the task objective and 2 distinct positive/negative probes before each update; include one regime where earlier mutator choice is inferior under finite costs and another where preferred order is reversed. Compare original-source-matched enabled rule mutation, source-identical shadow-write suppression, frozen-R0, fixed-R1 and corrupted-feedback arms. A source-level mutation-rule positive control with the same immediate output but different NEXT source-paid bytecode edit is mandatory.
- Evaluate rule and program value over more than a single bit. Require a preregistered **credit-normalized performance denominator** and report whether lower-cost rules still maintain comparable held-out correctness; do not silently turn a low-credit world into a failure-excluded sample.
- Include an impossible target (no available A/B/C matches) to test that attempted rule modification does not manufacture task capability, and maintain a source-paid fallback.

## HARD strict 16/180/300 feasibility gate BEFORE any native implementation

Existing F1d1i code already occupies **157 of 180 native source nodes and 16 of 16 possible data keys**, with no spare distinct key for a persistent rule descriptor unless a prior key is **reused safely**. A plausible space-neutral candidate is `key21`: at initial entry it is an externally provided edit gate0/1, and both positive values1/2 could later denote actor-owned `R0`/`R1` while `gate=0` remains a source-identical suppression control. But **the safety and information-flow implications of mixing a host-provided authority gate with actor-controlled evolution state are nontrivial**; do NOT implement this without a source-visible check preventing PID1 from converting initially disabled gate0 into enabled write authority. Prefer structurally distinct data-memory roles via charged cell recycling/reencoding if possible. Because modifying the mutation-rule decoder, credit sensor and retargeting requires more than a trivial 23-opcode extension, the foundation may need a **new preregistered founder source**, not direct blind append to F1d1i.
- Before writing native Rust test source, commit an independently checkable native CIL source graph, register map, **all reachable cell keys plus paid Delete/reallocation policy**, resource budget and held-out/feedback schedule. Source-only feasibility may reject the design if 180 native nodes /16 live data cells /300 occupied total cannot accommodate a real paid rule update. Preserve this as a **negative capacity result** rather than increasing kernel/world limits or moving the rule computation into Rust test code.
- Must never relabel PID2 as same individual, replace PID1's CIL graph externally, transfer extra host credits, patch a hidden task identity into data, or count a prewritten complete candidate source branch as actor invention.

## Acceptance logic and independently verified falsification

A narrow true positive needs **the same original PID1** to (a) pay to evaluate at least two task program candidates, (b) pay to update a persistent data-encoded rule descriptor based on actual feedback/cost, (c) later pay to generate **different NEXT virtual-program slot Writes** based on that new descriptor (not solely the same fixed mutation order), (d) successfully reexecute a score-selected program on separately supplied held-out data after a task shift, and (e) remain within strict resources. Compare source-identical shadow-write controls; **independently reexecute all original native CIL instructions and external interventions**, and reject first divergence.

Even a positive result here would establish only **adaptation among preauthored mutation policies**. It would **not** satisfy novel opcode-semantics invention, original F1c founder origin, authenticated B53 monitoring, strict N56-A/B/C, B3/B4, open-ended cyberlife or human-equivalent self-organization. A negative 16/180 substrate-capacity finding is scientifically valuable and should be reported transparently.
