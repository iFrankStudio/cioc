# CL-1B B56-F1d1i — prospective adaptive bytecode mutation, program rollback and regime-shift retention

**PRE-REGISTERED BEFORE ANY F1d1i NATIVE IMPLEMENTATION, CONTROL OUTCOMES OR RESULT.** This is a mechanism-falsification study and must not be confused with established adaptation to arbitrary tasks, autonomous semantic invention, B3/B4 or cyberlife.

## Starting point and unremoved shortcut

F1d1h [full CI run44297799709](https://github.com/iFrankStudio/cioc/actions/runs/44297799709), independently reexecuted 14,781 actual native paid instructions across 36 same-PID worlds, showed candidate-specific scoring and held-out winner retention under strict 16-cell/180-node physics. The investigator still authored and fixed the **entire** enumeration A→B→C and score-tie rule. A matching held-out output after that fixed enumeration does not prove the agent could choose *which experiment to try next*, react when the environment changes, or return to a previously successful program after later failure. The next study must attack precisely that limitation, rather than accumulate arbitrary additional test seeds.

## Prospective hypothesis and hard negative

H1 (bounded): a **single original PID1** uses feedback about its actually executed current data program to select the *next proposed bytecode edit* among at least two nontrivial alternatives and keep/restore a better program after a change in hidden task, without a host-picked candidate, source-code change, new PID, hidden fitness oracle in memory or free state reset.

H0: the actor always follows the preauthored fixed A→B→C sequence or a hidden-task-index lookup, so apparent 'adaptive mutation' is only a replay of a fixed manually ordered curriculum. Any fixed sequence that coincidentally does well on a prespecified task order fails H1 absent a separate source-identical counterfactual where feedback reverses the **actual next mutation**.

**Required strong within-PID counterfactual:** start from **byte-identical** original founder source and bytecode, matched input and budget. Change *only* the ordinary post-service feedback bit that PID1 reads. The actual next PID1-paid data-program mutation **must differ** between control arms before any human intervention on program memory. Record original virtual program slot contents and PID1 CIL Write origins. It does not suffice for feedback merely to stop a fixed candidate sequence.

## Strict native environment and feasibility gate

- **Do not alter kernel physics**. `World::with_strict_capacity(16,180,300)`, one original PID1 only, ≤180 initial CIL source nodes, ≤16 *simultaneous* data cells, ≤300 total occupancy, finite actor-paid credits bounded and preregistered per world. No GraphLaunch, no externally edited bytecode/program/winner/scores, no host initial opcode graph changes within an arm, no privileged credit reset.
- F1d1h used 166/180 native nodes, exactly 16 potential shared cells and peak183/300 total occupied. Only **14** spare native code nodes and **zero** spare potential cell keys remain if that source is copied unchanged. The implementation **must first reduce/restructure the controller or reuse existing paid cells**, with a prospective source/PC/branch manifest and an explicit key-liveness check. A protocol-preserving negative capacity result should be reported, not hidden by increasing limits.
- Retain the same small researcher-authored virtual ISA only as a **controlled feasibility substrate**; do not claim its opcodes or mutation operator were invented. The actual candidate mutation instruction(s), program positions and input-feedback translation must be executed by PID1 through paid native CIL writes, not determined by the Rust test harness after seeing the hidden task.
- Require **at least two real probe services per retained candidate** and a third independent held-out input for each evaluation phase. Use both positive and negative input values, and reject functional alias cases. If the VM cannot afford two probe services under the finite budget, preserve the stopped world as failure instead of skipping expensive operations.
- Maintain an explicit **prior-best program state** with actor-paid storage, and after an environment regime shift require PID1 to test its previous winner against fresh feedback. Its response must either retain or change/rollback the executable data program and demonstrate held-out consequences. The environment may change its hidden oracle, but may write only ordinary input/feedback cells and no candidate metadata.
- Freeze at least two task-shift orderings (e.g. IDENTITY→COMPOSED, COMPOSED→NEGATE) and include adversarial signal regimes `TRUTH`, `INVERTED`, `BLIND_SUCCESS`, `ABSENT` alongside same-source edit-disabled controls. Call `BLIND_SUCCESS` **unhelpful present feedback**, not absence; `ABSENT` is read as default0 unless a separately authored provenance sensor is included, which cannot magically authenticate truth.

Execute original native Rust worlds, preserve failed/trapped worlds, record **every** process PC/register, charged operation/credit, opcode fetch, interim accumulator, all bytecode-slot edits, rollback, winner state and external intervention. Independently reexecute the exact source and every native event via a new JS CIL observer; fail closed on first divergence, omitted probe, source mutation or new PID. CI native and observer denominators must be updated explicitly.

**Scientific interpretation:** passing this would demonstrate **feedback-conditioned selection among researcher-given bytecode mutation operators and rollback under task shift** for one continuous process. It would NOT show invention of primitive instructions, new learning rules, unbounded open-ended evolution, original F1c entity continuity, N56-A/B/C, B3/B4 or cyberlife.
