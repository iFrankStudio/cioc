# CL-1B / B10 — CIL-native evidence freshness under stale and injected markers

**Prospectively registered 2026-11-15 before B10 implementation or outcome inspection.** A *human-authored* native-CIL freshness protocol, not emergent life, unscripted adaptation, or intrinsically trusted observations.

## Research question

B09 failed to distinguish a valid-zero output from a missing cell, or a fresh output from stale matching data. Can a single CIL actor avoid those two ambiguous readback cases by **deleting a marker cell itself before each trial**, requiring the service code to produce a fresh nonzero marker, then detecting its absence? Does that solve freshness **only** under a defined threat model, and fail again if a hostile environment injects a matching marker *after* the actor's deletion?

Only existing generic `Delete`, `Read`, `Write`, `ReadNext`, `Sub`, `Branch`, `PatchNext` and `Const` are allowed. No host task oracle, code restoration or guaranteed checkpoint correctness. This is an engineered local proof-of-mechanism.

## Frozen single-founder CIL program

One process id1, initial 200 credits, strict world storage64, input in shared key7, output in key11 and freshness marker key13. All instruction attempts cost one. No pool or new process. Source code has exactly20 nodes:

| PC | CIL operation | next / branch |
| --- | --- | --- |
|0|Const r0=6 (editable service entry)|1|
|1|Const r2=13 (marker key)|2|
|2|Delete cell13 **inside CIL**|3|
|3|Const r2=7 (input key)|4|
|4|Read r1,cell7|5|
|5|Const r3=1 (nonzero marker value)|6|
|6|Const r2=13 (target: normal next7)|7|
|7|Write cell13=1 **native service marker**|8|
|8|Const r3=11 (output key)|9|
|9|Write cell11=r1 **native service output**|10|
|10|Const r2=13 (marker key)|11|
|11|Read r2,cell13|12|
|12|Branch r2 nonzero17 / zero13|—|
|13|ReadNext r1,node=r0|14|
|14|Const r3=3|15|
|15|Sub r1=r1-r3 (calculate candidate target current edge−3)|16|
|16|PatchNext node=r0,target=r1→17|17|
|17|Const r2=13|18|
|18|Const r3=11|19|
|19|Const r0=6|0|

External lesion at node6 next7→10 bypasses *both* the marker write and output write. On each trial actor deletes any old marker, then sees missing marker (=0) and attempts to repair. The correction formula (current next−3), marker value, selected site and diagnosis policy are **researcher-authored**. No experimental outcome qualifies as autonomous code search.

## Fixed matrix: 5 input labels × 5 arms = 25 native deterministic worlds

Input labels `[-13,0,7,23,101]`; each world receives external founder load, `SetCell(7,input)`; all have a source-identical program, 200 initial local credits, no compute pool.

1. **INTACT**: no host code damage, no preseeded marker/output; correct output and marker generated by CIL, no native repairs.
2. **DAMAGED**: external `PatchEdge(process1,node6,next10)`, no preseed; first marker read after bypass must be0, and CIL restores edge 6:10→7. Correct outputs later, including when input0.
3. **STALE_BOTH**: external preseed output11=input and marker13=1, then external `PatchEdge(node6,next10)`. Native PC2 Delete must clear stale marker before trial; restoration and fresh PC9 output still occur even at input0.
4. **DAMAGED_PATCH_DISABLED**: same code lesion, `with_native_patchnext_disabled()` world-law control before execution. Marker repeatedly missing, paid attempts to patch are suppressed; no successful native output or edge restoration.
5. **POST_DELETE_MARKER_SPOOF**: external code lesion. **After** native PC2 Delete and PC6→PC10 traversal, but **before** PC11 Read, researcher externally sets cell13=1. The trial's first marker read is forged matching even though PC7 marker write and PC9 output never occurred. Later iterations without spoof may repair, but **first decision must be a false accept**. This arm is a clearly labeled adversarial external intervention and must not be mistaken for CIL-generated output. The host does not directly modify code after the initial lesion.

All arms except POST_DELETE_MARKER_SPOOF run 80 CIL attempts in one invocation. The spoof arm runs until PC11 first becomes next, injects exactly one external `SetCell(13,1)`, then continues until **80 total native attempts**; intervention does not consume a CIL attempt. Trace PC2/PC7/PC9/PC11/PC16, program next edge, actor identity, external/internal provenance and compute inventory.

## Preregistered primary endpoints

- Correct marker0 absence for first trial in damaged arms (without spoof), correct marker1 on intact arm; source's `Delete` at PC2 must be executed from **Origin::Internal(1)** each new iteration, including STALE_BOTH.
- No native output at PC9 in any uncorrected damaged trial; all eventual valid output writes must originate at PC9. A preseeded matching output is not a native output.
- **Exactly one** effective native edge restoration for DAMAGED and STALE_BOTH and the ordinary POST_DELETE_MARKER_SPOOF arm *after* the initial spoofed decision; zero effective restorations for INTACT and PATCH_DISABLED.
- STALE_BOTH must restore even with input0. POST_DELETE_MARKER_SPOOF must **not** repair before first spoofed-marker read decision, and must record that a forged marker caused a false accept in the initial damaged trial.
- Every world: exactly one process, zero births and traps, 80 native attempts and ending compute inventory/local credits120, no hidden host intervention after declared timings. Count all failed trials, no filtering.
- If the spoof cannot be injected precisely before the first PC11 Read, **fail the experiment**, do not cherry-pick a favorable step offset.

## Interpretation and next gate

Freshness is always **relative to a threat model**. Under only stale pre-existing state, internal deletion followed by a nonzero marker distinguishes absent service from valid-zero output. If an attacker may alter the marker between reset and observation, this simple protocol can be fooled. A credible self-maintaining cyberlife cannot assume all evidence channels are invulnerable. Next research must require agent-proposed probe variants with independently measured information gain/novelty and cost, held-out spoof/lesion trials and policy corruption, without replacing the source of trust with a new hardcoded host validator.
