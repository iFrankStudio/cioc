# CL-1B · C11 原生有偿服务计量的成本门槛（先冻结，后运行）

**日期：2026-11-23 UTC。状态：PRE_NATIVE_FROZEN。** 本方案在任何 C11 新原生运行之前提交；已有公开 C10 数据用于成本校准，**不是新的隐藏测试集**。本实验是工程可行性与经济性反例试验，不能作为 B3/B4 的自主适应证据。

## 研究问题及零假设

C10 已有 PID1 原生付费存父值、写回旧物理 PC173 和实测费用收益，但 PC95→PC102 的触发信号来自研究者预先编好的 cell36。C10 原始 45 对同源物理效果比较累计节省 1840 CIL；仅凭服务序列不能精确推出所有计费差异。现在先问：**PID1 能否不靠宿主免费计数器，自己用普通 CIL Read/Add/Write 支付代价，持久记录原生服务次数？监控成本是否会吞噬已知回退收益？**

- H11-math：每一次实际原生有偿 `Write11` 服务后，插入恰好 **6 条有偿 CIL**，真实保存 `cell43` 为截至当前第几次服务；没有主机 `SetCell43`，无免费 Reader、Fitness 或 ReadCredits。
- H11-transparent：同一案例、同一反馈方式下，在剥离 C11 新增加的6条原生指令后，原有 C10 PID1 的每条旧源码执行顺序、服务猜测/反馈、真实 PC28/PC102 源码修改、完成48任务的情况应与对应**不同原始源码**的 C10 参考臂完全一致。实际总指令费须满足 `metered_cost = reference_cost + 6 × number_of_service_Writes`。任何一处失配、源图修改未计费、资源超限或真任务未完成都判失败。
- H11-economy：对 45 个 C10 旧案例比较 `metered_live` vs `metered_pc102_suppressed`（二者具有**完全相同 C11 初始源码**），并跟原有 C10 无监控源的两臂核对。报告**监控毛开销、按真实服务数变化的开销、净费用比较、监控成本相对于 C10 累计回退节省1840 CIL 的比例**；禁止预设结果为正。监控读取次数不等于精确逐指令成本，不能把服务尝试数当作“免费成本仪表”。

## 精确原生源码改动及收费边界

以 C10 已冻源 `frozen_source_g2_rollback`（180节点）为共同亲本，禁止改动原有算法/参数/回退规则，仅修改 PC3 原本 `Write(addr=r2,value=r3,next=4)` 的 `next=180`，顺序追加：

| PC | CIL 通用指令 | 下一PC |
| --- | --- | --- |
| 180 | `Const r2=43` | 181 |
| 181 | `Read r0=[r2]` | 182 |
| 182 | `Const r2=1` | 183 |
| 183 | `Add r0=r0+r2` | 184 |
| 184 | `Const r2=43` | 185 |
| 185 | `Write [r2]=r0` | 4 |

在执行 PC3 后，原有 PC4→PC5 会覆盖 r2/r0，所以计数器不应该改变原决策；这是**可检验预测**。严格容量：**最多16个数据键、186个源码节点、300总占用**，初始已使用187（原C10是181）；全部世界初始6000私有计算信用，不补给；只需已有 CL-0 Rust 内核及通用操作。原C10使用15个数据键，新增 `cell43` 后最多16个。计数不是主机注入的；原本任务 feedback `cell20` 仍由环境提供且明确标记为 external。

## 实验矩阵与对照

使用 C10 已公开、原样冻结的 **45例×48隐藏真实目标**（5族各9），**不是未知环境的泛化测试**。每例4臂：

1. `metered_live`：同C11监控源码，PC102真实恢复物理PC173；
2. `metered_pc102_suppressed`：同C11完整初始源码、仍支付PC102，只由研究者抑制PC102对PC173的**物理**效果；
3. `reference_live`：C10原180源码、正常回退，作为**不同源码**的监控成本对照；
4. `reference_pc102_suppressed`：同C10原180源码、只抑制PC102效果。

另对主源 `metered_live` 追加 C10 预先确定的 `inverted` 与 `forced0` 反馈负控（各1个），同一验证不删除错误反馈；原先 C10 的其他诸臂不混计本实验。共 **182 个原生世界**，全部进入总账。所有源都运行在相同通用的16-cell/186-node/300-space平台、相同原生计费内核，比较时不得称“不同源码监控差额”为严格同源计量效果因果消融。

**原始可复现性门槛：** Rust 新原生 CI 运行180真反馈+2欺骗反馈，输出逐指令及每次服务后的完整原生记录、所有世界不丢样本；独立 Python 解释器根据两个原始源图分别执行全部原生步骤、计数器、存储和环境反馈，严格核对每条PC、下一PC、4寄存器、收费余额、逐键数据、物理PC173值、动态代码编辑和服务结果。强制确认 `cell43 == 本世界累计实际Write11次数`、最后源图变化等价性、全额算力账以及第一条C11监控指令不改变任务目标。任一预算透支或原生—解释器不一致则原生实验 **FAIL**。

## 预先规定的报告口径和后续门槛

逐例报告服务次数 `N`、原生计费 `T`、C11额外费用 `6N`、净效益 `Δ = metered_suppressed_cost − metered_live_cost` 以及旧C10对应的净效益；同时区分单个案例、整45例、监控开启前的1840节省。若C11计数器虽然真实收费但不影响回退决策，只证明“可计数”，**不证明自我测量优化、内生ROI估计或学会自主变异**。C12或后续实验若要计入 B3，必须让主体真正读取/比较这种有偿证据、根据新环境主动选择保留/回退，配同源码效果消融、强策略基线及事先未见任务；禁止把C11结果称作生命诞生。
