# CL-1B B51c — native paid parameter search, feedback selection, and lasting code routing

**Prospective registration, 2026-11-17.** Frozen before this B51c experiment's first native execution. Earlier B51b tests established that fixed candidate templates `x+2` / `2-x` cover only **2/8** of the previously preregistered eight affine modes. B51c therefore investigates a **strictly richer, continuous single-actor mechanism**. It does *not* revise, retroactively accept, or replace the B51 top-level hypotheses; H51b/H51c and B3/B4 retain their original burden.

## Fixed, testable hypothesis

The original B51b two-candidate graph cannot identify a correct program for the other six modes even with perfect feedback. **H51c-search (narrow engineering):** starting without any connected task-correct arithmetic route, one PID1 CIL actor can *pay* to connect two distinct operation templates into executable candidates, enumerate parameter guesses through native arithmetic and stored data, submit two discriminating nonzero training probes for each candidate, observe only one post-Write external feedback bit through normal charged `Read`, and retain a persistent executable route **only when both probes succeed**. In all eight hidden modes the retained route should correctly produce heldout outputs, without a host source patch, mode/answer label exposure, target-specific code resynthesis or process replacement.

**H51c-selection causal test:** under the *same initial* 1,300 charged CIL opportunities, source, task order, source-edit affordances and output-scoring rules, truthful paid feedback must beat a blind feedback-always-success arm in aggregate heldout **correct writes minus wrong writes** across all eight modes. Each mode remains in the aggregate, including the one that blind selection can solve without search. Failure falsifies this causal hypothesis. A static **per-mode six-instruction oracle** is a stronger upper-bound control; matching or exceeding that oracle is not required for this narrow substrate demonstration, and its opportunity-cost advantage must be reported. This is intentionally *not* acceptance of endogenous B3/B4 or B51d out-of-family transfer.

## Frozen experiment design

- Eight externally hidden modes `f(x) = s*x+k`, `s∈{-1,+1}`, `k∈{-3,-2,+2,+3}`. Fixed enumeration is sign `+1` then `-1`, with candidate offset `k=-3,-2,-1,0,1,2,3` in each sign. The two generic `Add` and `Sub` templates and a generic `Write` begin disconnected from the actual task input route; an authored generic CIL controller *pays* `CloneNode` and `PatchNext` to create/activate these graphs. **Only the task family, candidate grammar and search controller are researcher-authored.** The lab never selects a winning candidate or patches code.
- Training probes **x=5 then x=-3**, always two paid native candidate output writes, for each candidate. An external experimenter observes the real actor-origin `Write` to cell11, scores against the **most recently externally supplied task input x** and the hidden laboratory s,k, and writes only a one-bit feedback success `0/1` to normal cell20, with `Origin::External`. Next input x is externally supplied. The actor must pay a subsequent `Read` for success. Only if both probes succeeded may the actor pay `PatchNext` to retain its executable task route.
- After real actor-origin retention, the lab switches to heldout x cycling **[11,-7,0]** and never supplies fresh correctness feedback. All actual actor-origin output11 writes during holdout count against the corresponding externally frozen x; a right numeric value produced by the wrong candidate on a single x is not considered a retained whole-task solution. The external lab must not read/write actor program code, compute credits, candidacy/retention cells or target answer data.
- Original CIL actor starts with **1,300 local paid instruction credits**, strict storage <=192, data cells <=16 and CIL nodes <=120. No compute refill, world-targeted top-up, second process, host optimization opcode or task-specific per-mode founder. All eight TRUE and eight BLIND arms retain **exactly the same founder code**, evaluator and initial resources; only the one-bit training feedback content differs.
- **TRUE** arm receives genuine post-output success bits. **BLIND_SUCCESS** receives constant one bits despite real post-hoc external scoring; both arms pay for the same feedback Read opcode and source modification opportunities. Record actual charged steps, candidate trials, clone count, edge mutations, input/feedback provenance, storage, stopped worlds, remaining budget, heldout correct/wrong counts and discovered sign/offset. Distinct source graphs (Add vs Sub) and distinct generated parameter records must be evidenced as actor-origin; do not reinterpret authored search as emergent mutation grammar.
- **PATCH_DISABLED** on at least one preregistered hidden mode (s=-1,k=3): preserve source and budget but suppress ordinary `PatchNext`, and record whether it can ever construct a real executable candidate or write correct service output. This is a substrate-negative control, not a matched-exposure functional learning comparison.
- **STATIC_PER_MODE** each of eight modes: a separately researcher-authored compact correct six-op loop, same 1,300 paid credits and same heldout input cycle. Label it a laboratory *upper bound* that already knows s,k, never evidence of native endogenous learning. Count output correctness under the same opportunity budget; do not exclude its superior efficiency when reporting a positive comparison.
- **All** arms must be retained in the scientific denominator even if halted or unable to acquire the hidden mode. Zero writes are zero output, not successful adaptation.

## Exact reproducibility requirements

- One source-pinned Rust native integration target writes an evidence JSONL with actual paid CIL `step` rows and explicit externally originated `input` and `feedback` rows for **all 16 TRUE/BLIND worlds**, then complete end records. The 8 static controls and patch-disabled control additionally report native end summaries. Record the Rust source SHA, CIL founder initial graph length, actual register/PC and dynamic code successor/clone state at every step.
- A completely separate JavaScript CIL interpreter must read the *real committed Rust founder instruction literal*, independently pay every CIL attempt, apply the precisely preregistered external task protocol and compare every actual native step **and** final state/count. Missing trace, incomplete or premature records, source mismatch, divergent event origin/value, unknown opcode, or violated credit/storage law must fail the CI job closed. An aggregate-only source-pattern scan is not verification.
- The scientific test may fail H51c-search or H51c-selection without failing the engineering CI harness: do not assert hand-picked favorable output totals. Preserve failed worlds and archive native traces; classify H51c status independently.
- Predeclared train/holdout values are not randomly sampled or secret from the research code; this limits generalization. Heldout **task family**, delayed/stale-feedback attacks, cumulative multi-regime adaptation, mutation-rule authorship and B3/B4 are **NOT** tested here, and cannot be claimed even if all eight hidden modes are solved.
