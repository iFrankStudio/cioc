## F1c scientific question and information boundary

Test whether the **same actor-built two-monitor grammar** can select a useful monitoring policy on the basis of actually discriminating, paid, actor-observed evidence. The current F1b ecology switches only AFTER both candidate trials have ended, so the future-shifting and permanently stationary worlds present **identical input/output/feedback prefixes**, making a generally correct future policy choice information-theoretically impossible from those observations without an explicit prior, paid nonzero sensing floor, or a new legitimate environmental cue. **Do not add a future-task label, host-selected winning policy, reward opcode or task-aware oracle to the actor.**

F1c must distinguish these concepts rather than conflate them: (1) *charged composition of two monitor graphs* (already demonstrated), (2) *fair candidate trial observations* (not yet), (3) *internal feedback/cost-based preference* (not yet), and (4) *positive utility against the strongest fixed policy* (not yet). Strict self-authored generator mutation is a separate N56-C gate.

## Preregistration requirements for executable implementation

1. Preserve one PID1 and the original exact task-search program for initial task retention. Candidate monitor assembly must be paid normal CIL `CloneNode`, `PatchNext`, `PatchConst`; retain both source topologies in the same individual's graph without a host-assisted patch. Publish the exact initial source node inventory and node liveness, including the **preexisting B51c training feedback**. No strict de-novo monitoring-origin claim permitted.
2. **Order-balanced paired trial windows:** at least four deterministic seeds with both A(EVERY)→B(FOURTH) and B→A orders. The actor itself must select order using an ordinary prior cell or deterministic internal computation, but no lab branch/host PC patch during trial. Both actually execute the same number of native service requests under each prospective trial condition, and trial costs (paid steps, feedback Reads and source allocation) remain visible.
3. **Two independent trial ecologies**, with source-identical trial orders and matched initial task grammar: a stationary task where both monitors see valid success bits, and a discriminating task with an unannounced change *inside* a candidate trial window. Hold out a further shift/return after the selection event. Candidate trials must not be selected by task-specific offsets/timestamps tuned from outcomes, and the task label is never written into PID cells. Count all missed outputs and credit exhaustion.
4. **Internal cost accounting**: ordinary cell counters updated through actual paid CIL `Read/Add/Write` for monitored correct/wrong outcomes and measurement work; the CIL actor compares source-local results, not Rust-side summary statistics. Explicitly differentiate sample count from true failure count; a false success or unobserved failure cannot count as a valid learned observation. Report whether choice changes under source-identical blind feedback.
5. **Controls**: truthful two-generated-monitor learner, source-identical constant-success/inverted feedback, source-identical fixed/random choice, static EVERY, static FOURTH, no service monitor, and a **clean monitor-only edit suppression** triggered only after the original task program has correctly retained (avoid B56 F0's whole-life mutation-disabled confound). If existing native world physics cannot provide this precise intervention under the original kernel, preregister a generic world-law/control change **before** native outcomes, or mark the control unavailable and full F1 unfulfilled; never silently drop it.
6. **Finite resource gate**: first attempt equal 4,000 charged CIL steps, <=16 data cells, <=180 program nodes, <=300 total storage for all controls. If order reversal or costs require more, freeze a new explicitly numbered enlarged budget **before any native run** and compare source-matched baselines at exactly the same cost; do not retroactively re-score the F1b run.
7. **Independent replay:** every native-paid instruction, source node mutation, exact output value, feedback origin, register/PC/credits, data-cell history, external task schedule and actual source path after selection must be independently replayed from exact Rust CIL source with repository SHA and manifest hash. Report exact first divergence and keep failed native/JS runs.

## Frozen acceptance and falsifiers

- **F1c order-balance mechanism-positive:** both structurally distinct, actor-assembled, actual monitored service paths execute under at least two orders and all registered seeds, with no host source mutation; no source inventory falsifier. This remains researcher-authored assembly, not strict N56-A.
- **F1c causal preference-positive:** paired truthful vs blind and stationary vs discriminating histories produce **predictably different paid PID1 retention choices** according to genuinely sampled valid evidence (not training task correctness, not input phase, not host hint), and a further independent hidden test validates that those choices serve their original cost/error tradeoff. If the actor always picks FOURTH or if choices differ only by arm seed/order, reject causal selection.
- **F1c utility-positive:** strict paired superiority to BOTH static EVERY and static FOURTH on preregistered full-budget `correct service outputs / paid instructions` AND noninferiority on `(correct−2·wrong−missing) / paid`, with all task-shift epochs and completed/missing windows reported. A mechanism-positive but utility-negative outcome must **NOT** satisfy N56-B usefulness.
- **Full F1 acceptance remains conditional** on all original B56-F1 preregistration gates, including a monitor-specific edit-disabled control, nonaffine capability boundary and blind/forgery controls. No later partial study silently replaces the original experiment. **N56-C mutation-generator self-revision and cyberlife are separate hypotheses.**
