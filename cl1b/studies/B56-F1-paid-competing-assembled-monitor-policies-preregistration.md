## What the next falsifier must distinguish

B56-F0's single authored assembler ran even under a constant false success bit, and the edit-disabled control disabled the *original B51c task search* as well as later monitor assembly. Therefore F0 does not yet establish that the individual **needed feedback to choose a useful new monitor**, nor that monitoring-specific source edits alone caused an improvement. **F1 asks whether one continuous PID1 can generate and test two structurally distinct complete service-monitor topologies from generic parts and choose between them through actual source-paid evidence, without an oracle selecting the answer.**

No ready-to-route complete EVER / FOURTH / NEVER monitor subgraph in the A/B/F1 founder. The graph may include **ordinary inert instruction templates**, a clearly declared researcher-authored (and falsifiable) assembly/search grammar, and the already verified B51c arithmetic task searcher. This remains an engineered grammar, not an origin-of-life result.

## Prospective design and controls

- **Source inventory first**: commit the initial Rust CIL graph and a complete node/edge/constant manifest *before running native tests*. F0's 102-node source contains a prepared feedback branch and failure-marker path; do not count merely duplicating that branch as a fully unplanned policy. Hash the founder's actual serialized graph and record source-tree SHA.
- **Actual paid generation**: the actor must create **two distinct monitoring graphs** through paid `CloneNode`, `PatchNext`, `PatchConst` or available generic CIL primitives. For example, graph1 monitors after every Write; graph2 has an actor-paid counter and monitors every N outputs. If the two graphs differ only by a single preauthored selector value, reject the structural distinction. Report all failed generated source edges and no-op edit costs.
- **Within-PID experiments**: the same PID pays for **actual service trial windows for BOTH generated candidates** before retention, including source-swap costs, external feedback Reads and service outputs under frozen hidden task schedule. Candidate trial order must be counterbalanced across seed/phase and must not leak later mode switches.
- **Truly actor-observable evaluation**: no task label or correctness function in PID-visible data, no host choosing a winner. If the laboratory provides a feedback bit, treat that as an externally trusted *assumption*, include a fake success/current-ID lie control, and instrument whether the candidate compares *cost paid* using an actor-visible ordinary counter rather than investigator-side output statistics.
- **Matched ablations**: (A) truthful PID-generated trial+selection, (B) identical source but constant/blind success, (C) original task program *allowed* to form, but only monitor construction source mutation subsequently disabled by a preregistered generic world rule (avoid F0 C's confounded whole-life edit suppression), (D) preinformed static EVERY, (E) static FOURTH, (F) source-identical no-monitor, (G) random/fixed policy choice. Static baselines must be clearly marked as separately authored sources if they have complete controllers at load.
- **Original resource envelope**: initially seek **4,000 paid CIL credits, <=16 cells, <=180 source nodes, <=300 storage**; if two newly constructed monitoring graphs cannot fit, file a **capacity failure** under these limits. A different budget needs a *new*, pre-run capacity/utility manifest and source-matched baselines, never post hoc changes in F0.
- **Original task schedules**: retain paired hidden task A `x−2→−x+3→x−2` and B `−x−3→x+2→−x−3`, training x `[5,-3]`, heldout x `[11,-7,0]` and 24 output positions per three stages, including 0-output worlds. Add one withheld *non-affine* mapping as an explicitly capability-limited pressure test; do not inject a solver.
- **Independence**: trace each real Rust paid instruction, clone, code-node change, counter, external intervention, correctness opportunity, PID origin, credit and storage delta. Separately parse real Rust source into an independently written CIL interpreter and replay every event. A source-bound hash or any event divergence fails the positive outcome.

## Acceptance thresholds fixed now, executable details to be frozen before F1 source

**F1-assembly (N56-A second instance):** actual paid two-topology assembly, no complete monitor in inventoried founder, both paths actually used under one PID.

**F1-causal selection (candidate N56-B only):** chosen policy must be based on actor-paid, discriminating evidence in comparable trial periods; strict source-blind/constant-success counterfactuals should change the chosen policy or lose functionality. If source assembly and choice occur with no informative feedback, reject causal learning.

**F1-useful advantage (candidate N56-B only):** require a *paired source-pinned* improvement over **the best** static baseline on predeclared full-budget correct-output throughput and a separately reported `(correct−2·wrong−missing)/paid` utility, with no hidden shift epoch being wholly sacrificed. A policy with fewer wrong outputs but fewer full-budget correct outputs must report the trade-off, not automatically pass.

**F1-generator revision (N56-C):** NOT part of this initial F1; register a separate stronger experiment requiring native edits to the actor's **generator itself** after a hidden regime change. Selecting from two generated policies with a fixed authored generator is *still not* endogenous evolution of the mutation rule.

**Fail closed:** no positive result if whole-life mutation-disabled control prevents the task program from existing, no monitor-specific causal ablation, or missing raw code edits, and do not infer life from only 4,000 paid deterministic VM instructions.
