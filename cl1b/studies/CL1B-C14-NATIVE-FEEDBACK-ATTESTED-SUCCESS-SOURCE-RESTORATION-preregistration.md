## 问题：历史成功“代码证据”能否指导后续真实代码恢复？

C13单PID1已能自费记录、读数、在原生程序中选择是否执行PC102，但固定阈值是研究者预先编写，且新30案例中真实物理恢复5次没有产生任务费用差，反而额外付费458。C14不再记录空泛的事件次数，而是研究**成功反馈与物理代码值配对**：在原生任务Write11获得可用外部反馈20后，原程序在PC5有费Read20、PC6有费Branch；仅当反馈非零，PID1再有费读**它先前实际执行过PC173，并经过有费PC52 Write41存入的数据**，将那个代码值写入另一个真实收费数据单元44。后来旧C10真实有偿恢复触发PC95非零时，不再读“最近的父物理源码值”cell42，而是真正有费`Read44→PC102 PatchConst PC173`，重用**过去实际通过服务反馈的活跃代码值**。

这是**研究者编写的成功样本记忆及恢复政策**，并非自己发明学习算法；外部反馈20可能被伪造，故这种“成功”最多是反馈声明，不是认证真实成功/适应度oracle。

### 新原生184节点完全冻结代码变更

使用原C10 frozen `frozen_source_g2_rollback` **180个原始节点**，只改两个字段并追加4个通用CIL原语：

- 原`PC6 Branch(test=r0,nonzero=29,zero=7)` → `nonzero=180`；真实失败仍原路7，真实成功才进入新有费路径。
- 新`PC180 Const r2=41→181`，`PC181 Read r0=[r2]→182`，`PC182 Const r2=44→183`，`PC183 Write [r2]=r0→29`，继而继续原成功逻辑。
- 原`PC99 Const r2=42→100` 改为`Const r2=44→100`，从已经付费写入的“最近一次成功源码样本”提取回退值。旧`PC97 Write42`父物理值仍正常收费存档，以便同源机械证明实验确实改变了读取位置；但它不再供主回退使用。
- 仍然只有1个PID1；16个数据单元上限（C10原15个+新44），184个CIL源码槽上限，300总占用上限，每世界6000私有付费计算信用，**无内核改动、无免费Fitness/ReadCredits、无宿主免费运行代码检查**。

测量时明确定义：服务`Write11`发生的真目标正确性由独立观察者判定；反馈位20由环境设定（含故意欺骗控制）。主体自身只看到`Read20`值，付费执行PC6成功路径后才写44。C14中这条“最后一次声称成功源码”记录不保证该参数在未来会有效——尤其在任务变化之后。若尚未观察到成功，cell44不存在，CIL默认Read取0，这是可证伪风险。

## 研究分母：45新案例×6臂＋4真实费用假反馈负控

45案例×6臂全用真反馈，各48阶段，并另加4个确切冻结假的反馈控制，共**274原生世界**：

1. `truth_success_restore`：同PID1自身付费把真实反馈成功对应的已执行PC173参数写44，未来自己付费从44读并真实物理恢复PC173。
2. `same_source_pc102_effect_suppressed`：初始184节点CIL完全同1，PC102付费执行但宿主**仅压制它改变物理PC173的效果**，是成功记录恢复效果的严格同源因果对照。
3. `same_source_host_force_success_value_0`：初始源码完全同1，但在每次主体真正付费写44之后，宿主另以有标记`Origin::External`的`SetCell44(0)`覆盖，测试其后真实有费Read44→PC102的因果依赖。它是**外部污染**，不计作个体证据。
4. `same_source_host_force_success_value_2`：同3覆盖为2，防止“污染值等于本来就会选的值”形成偶然假阳性。
5. `different_source_c10_parent_restore`：原180节点C10真正有费父版本恢复。注意**不同初始源码**，只能用于总体经济和服务对照，不能把净差当单纯父值切换因果效果。
6. `different_source_c9_fixed_abstain`：原180节点C9永不修改的强固定策略，仍真实收费；初始源码不同，不是严格同源恢复效果消融。

另4个欺骗反馈世界：主C14 inverted、主C14 forced0、force0 inverted、force2 forced0；其行为收费完整纳入274分母，**不可算48/48真实成功**。必须保存全部新任务（包括失败、超预算或主动停止）与真实反馈服务轨迹，不对“未完成48阶段”后验剔除。
