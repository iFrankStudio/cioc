## 可证伪的核心问题

C15的“来源认证”只证明cell44是PID1曾真实收费Write过的历史成功代码值，**不证明它仍与当时物理PC173一致、不证明本次使用会有净益，也不保证这份记录没有被重复消费**。本C16研究检验一个有限因果功能：PID1自己通过**普通CIL付费单元45**记录当前成功证据是否已被用作一次物理代码恢复；在真正产生新成功证据（从PC188有费Write44）以后才重新开放一次恢复，而不是按无成本宿主策略强行锁死。该算法仍由研究者设计，并非个体自主发明收益函数或开放式演化。

## 冻结的203节点CIL源码

基于C15原生194节点有费源码（PC180..188验证历史代码最后写者ID=1并付费Write44成功证据；PC189..193验证真正有费Write44的来源；PC102修改物理PC173且PC102.next=173保证后续真正付费原生执行）；只改三个已存在节点的跳转，并追加9个通用有费CIL节点：

- `PC188 Write44` 原`next=29` 改为`next=194`。`PC194 Const r2=45→195`、`PC195 Const r0=0→196`、`PC196 Write(cell45)=0→29`：*仅发生了真正的PID1有偿Write44成功样本后*，才有费签发“未使用”凭证；凡假反馈会令其签发，属于可证伪欺骗风险。
- `PC95 Branch(test=r0,nonzero=189,zero=86)` 原非零改为`nonzero=197`。`PC197 Const r2=45→198`、`PC198 Read r0=cell45→199`、`PC199 Branch(test=r0,nonzero=103,zero=189)`：当有费读取到cell45=1（该成功证据已消费），实际收费跳过恢复；否则继续到已有PC189..193真正有费`ReadLastWriter44`检查来源，禁止无来源记录的恢复。cell45尚未分配时CIL Read默认0，**后继来源检查会拒绝缺失cell44**，不会免费解锁。
- `PC102 PatchConst targetPC173` 原`next=173`改为`next=200`。`PC200 Const r2=45→201`、`PC201 Const r0=1→202`、`PC202 Write(cell45)=1→173`：确实执行了一次真正**有费**PC102之后，PID1自身有费作“凭证已用”记录，再继续进入**物理活跃**PC173并在原PC24→PC52有费重新读回与存41。即使PC102是物理相同值恢复也要真实消费凭证，不能免费撤回标记；若信用在PC102/PC202后耗尽须如实计停止和未完成。
- 全部源码仍是**单个PID1实际执行的可编辑CIL**，不增加专门“生命意识/适应度/回退成功”opcode，不用宿主兜底恢复，也不赠予计算。原始PC和新增PC的有费实际执行、信用守恒、可验证物理动态源码、last-writer以及cell45占用都必须在原始JSONL完整可重算。
