## How both distinct policies really formed

All A/B/C learning/control-arm original PID1 sources start at exactly162 code slots, with no host edit of source after launch, a founder derived from the original B51c 72-node authored affine search grammar. Only node50's *after-retention* continuation was researcher-modified to allow the second-stage assembler to run. Normal B51c's two actor-paid task-operator clones occupy new nodes162/163.

**Monitor A, EVERY:** PID1 pays `CloneNode` to copy template `Const20` (node35) and `Read20` (node36) into two fresh executable nodes164/165; it pays `PatchNext` to set `164→165→feedback Branch98` and `Write2.next→164`. This is an actual new executable post-retention service edge, not a host callback. It outputs to service and reads paid feedback on **four** genuine service writes.

**Monitor B, FOURTH:** The same PID1 subsequently pays `PatchConst node94 2→148` and `PatchNext node95.next 102→159`, reuses its generic clone/edge-wiring CIL program to clone two additional Const20/Read20 nodes166/167, attaches them after a separate **counter-based skip/compare/reset** graph `136..148` (counter data key28), then pays `PatchNext Writer2.next 164→136`. It runs at least four actual service outputs through this different source topology; every fourth output passes through newly cloned monitor B for a paid feedback Read. The ordinary actor service count key29 tracks completion of these two trial periods, and a researcher-authored selection rule at nodes150–156 checks failure marker25. If it observed a failure it can pay to select earlier monitor A via actor-created index cell42; otherwise source B remains live.

**Important scope limit:** the researcher authored **all of** assembler code, bridge, feedback branch and existing finite input/test grammar; the B periodic count skeleton `136..148` is present in the original initial162 code slots as disconnected authored instructions, and B51c already had a complete training-stage output→feedback circuit. Thus two new *service* entry paths were actor-assembled and did differ structurally, but these are **not** source-invented independent monitoring principles, and not strictly de-novo monitor capability under the stronger original B56 N56-A test.

## Remaining scientific requirements / next discriminating research

This successful native+independent run does **NOT** establish full prospective B56-F1: it lacks (i) a counterbalanced A→B/B→A test schedule, (ii) a clean mutation-disabled *monitor-only* ablation after original paid candidate-search success, (iii) genuinely discriminating actor-accessible monitoring quality/cost information in the two trial windows, (iv) third-party response current-ID forgery, (v) nonaffine heldout task or a privileged reference oracle, and (vi) a guaranteed useful paired improvement relative to the best static monitor. The current single authored selector cannot diagnose later hidden shifts without paying for exploration forever.

**No evidence for N56-A strict de-novo capability, N56-B useful source-generation/selection, N56-C self-editing mutation generator, B3, B4 or cyberlife.** A sensible next pivot is to distinguish changes in *the policy-generator itself* from mere repeated assembly, and to impose a resource opportunity cost on construction while providing genuinely informative observables for monitor policy choice. Merely adding another fixed branch to ensure a positive score would be a post hoc research artifact, not progress toward open-ended life.
