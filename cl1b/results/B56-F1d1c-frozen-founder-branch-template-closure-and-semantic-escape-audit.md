## Exact-source generative grammar proof

The original F1c founder combines B51c's72 source nodes with the B56-F1c two-monitor code to **162 initial source nodes**. The source-driven audit finds exactly **13 Branch nodes** at PC `23,44,47,61,64,74,98,106,117,120,123,144,152`; **every one tests register3**. By contrast, original B53's nonce/echo and nonce/commit comparison circuits contain **Branch(test=1)** at PC111 and117. The original F1c founder contains only executable `CloneNode`, `PatchNext`, and `PatchConst` editing primitives, with NO reachable `GraphEncode`/`GraphReplace` or other general field/graph replacement.

The verified original `cl0-world` Rust implementation enforces:
- `CloneNode` exactly clones a preexisting `Op` struct and appends the clone; no opcode or register-field generation.
- `PatchConst` modifies only a `Const.value` field; it cannot change the kind or operands of `Branch`.
- `PatchNext` invokes `next_mut()`, which explicitly returns `None` on `Branch` and `Halt`; it cannot change `test`, `nonzero` or `zero`.

**Induction:** initially every F1c Branch has `test=3`; every available actor-paid edit preserves the property. Thus no descendant generated by these edits can contain a literal B53 `Branch(test=1)`, independent of compute, node-count or storage bounds. This is a **closed-template capability barrier** for the unchanged founder, separate from B56-F1d1b's **13-node literal-append deficit**.

The separately authored F1d1c scanner examines ORIGINAL exact-source F1c native data (not a new F1d1c artificial native actor): **48 continuous worlds, 192,000 real paid CIL instructions, 26,432 external interventions, and all1,106 native changed source nodes**. Initial graphs and every reported actual executable source change retain Branch(test3); **zero Branch topology changes / zero Branch clones** in these particular observed histories. The independent F1c instruction-by-instruction CIL replay independently matches the entire native trace with first divergence null. Finite histories corroborate but are **not the sole proof** of the general source-closure claim.

## Narrow semantic escape (not yet built)

B51c original node60 is `Sub{dst:3,lhs:1,rhs:3,next:61}`. Under equality comparison of nonce/echo, computing `expected−echo` into register3 followed by `Branch(test3)` makes the same *zero/nonzero equality decision* as B53's `Sub(dst1)` + `Branch(test1)`. The new observer verifies **10 signed-64-bit boundary cases** of this equality decision with modular arithmetic and original source operands. This does **NOT** show an assembled receipt checker in an actual retained F1c PID1. Clobbering register3 can destroy other state, and existing Branch targets cannot be redirected by PatchNext. A source-legal full actor-paid circuit would also need nonce generation, 16-cell liveness, ≤180 nodes, original search reentry, and truthful/blind/forged controls.

## Research implication and strict next gate

The genotype's **instruction-template closure** is a stronger bottleneck than just insufficient code capacity. Merely increasing the180-node limit would not allow generating original B53's Branch register1. Future work must:
1. Either find a complete *register3-compatible* source-reuse map where fixed Branch destinations, donor operand fields, mutation budgets and original task search are all respected, then test it as **new F1d1d paid native actor**; or
2. Explicitly declare a **new founder architecture** that includes generic graph construction (`GraphEncode` exists in the world kernel but not in unchanged F1c) and test its effects on generative reachability and lineage/identity. Importantly, `GraphLaunch` creates a distinct process ID; it is not automatically continuous same-PID individual evolution.
