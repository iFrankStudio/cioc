## 重要机制：让父版本属于 PID1 的原生已付费物理记忆

C6 存“尝试安装的值”会被未生效的补丁欺骗；C7 已证明 PID1 可以实际执行 PC173 Const、获得当前可执行源标量θ，再自己付费 Write41 保存**已执行值**。C9在同一父体上增加**修改前保留父版本`cell42`**：

```text
C7 的 PC79 Const r2=41 → PC120 Read r0=cell41
    → PC57 Sub r0=r3−r0 → PC67 Branch
                  r0==0 → PC125 放弃修改
                  r0!=0 → PC1 Const r2=41
                           PC2 Read r0=cell41       [真实付费再次读取父θ]
                           PC96 Const r2=42
                           PC97 Write cell42=r0     [真实付费持久保存旧物理θ]
                           PC27 Const r1=173
                           PC28 PatchConst PC173=r3 [真实原生自修改]
                后续 PC173 Const 真执行→PC24→PC52 Write41保存新θ
```

整个世界仍严格 **16数据单元、180 CIL源码槽、300总占用、6000个私人收费CIL、单PID1、48隐藏目标**，原生Rust内核和虚拟机操作码**未修改**。为从C7原有180条源码中释放四个真实可执行槽，C9研究者在所有试验臂上**统一实施**两种具有明确来源证明的语义等价压缩：

1. 原C7 `PC0 Const r2=30→PC1 Read r3=cell30→PC2 Const r2=11→PC3 Write11`合为`PC0 Const r2=11→PC3 Write11`。原生初始`r3=0`、缺失cell30的Read返回0；每次重新回到PC0前，PC23已真付费`Write cell30=r3`，所以PC1的Read3不改变当时r3。
2. 原C7 `PC88 PatchConst(PC46)→PC96 Const r2=36→PC97 Const r0=1→PC98 Write36=1`中，这条路径每次由PC93 Const36→PC94→PC95零出口→PC86 Const r1=46→PC87 Const r0=1→PC88抵达，PC96/97只能重复设置已有r2=36和r0=1。C9将PC88.next改为98，复用PC96/97。
   
因此新C9源码仅改动C7七节点 **PC0/1/2/67/88/96/97**，所有比较臂均使用相同的上述循环/源压缩。**不能把节省下来的旧无效循环费用归入检查点收益**；C9主臂与不保存父值的bypass严格只差初始PC67非零跳转边，其他源一字相同，正确隔离真实检查点的CIL成本。

原生和独立重放共同核验：**59次真实有偿PC97 Write42，紧接2条付费指令之后对应59次真实PC28修改尝试**；所有59次 `cell42==当时物理PC173.value==最近一次主体真执行→Write41`，从未把拟写入的参数当已安装父值。研究者故意取消PC28物理效果但指令仍收费的严格同源负控中，**49次修改效果抑制**，之后有**33次付费真执行PC173读回**，证实主体保存的父来源和后来可观察的实际θ没有被意图值替代。
