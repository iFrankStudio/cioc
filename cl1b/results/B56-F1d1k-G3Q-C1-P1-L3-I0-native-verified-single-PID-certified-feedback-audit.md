## Why this is a real new one-PID integration (and its limits)

Previously, M2's uninterrupted original PID1 produced a 64-rule C0 coverage certificate, retained and executed a safe descriptor, self-edited a next control edge and Halted. Separately, F0's *different freshly created* PID1 learned to reuse an initial researcher-authored rule's middle byte from authentic task feedback after hidden goal shifts. That did **not** establish a continuous certificate→task-feedback causal loop in one individual.

I0 implements both in **one uninterrupted original PID1 per arm**:

1. A fresh researcher-authored candidate bank `[2,0,2]` is originally written by the actor through paid CIL; it reads and deploys all three rule bytes from owned cells51–53 into active native data cells62–64. This is a **researcher-authored candidate grammar**, NOT a descriptor invented/generated through C0's exhaustive 64-rule search.
2. Before any real task service, PID1 spends its own credits to run the **same native 3-byte CIL interpreter three times**, advancing its middle opcode through distinct trials. It pays `Write(7+mode,1)` for each actually observed output in native cells7/8/9, then pays to read all three witnesses and compare their sum to3. Complete three-mode coverage qualifies; a trap-like RESET tail with the same source length generates only mode0 and fails.
3. Only if the paid native witness check covers all three outcomes does PID1 pay to restore its original candidate middle byte, set its own phase state, and enter the **actual task service** `Write11` at CIL PC71. This is **not** a coverage certificate `Write11`; the structural witness phase has separate native provenance (PC130 and own phase21).
4. The external harness provides the **single generic `SetCell20` feedback bit only after** native source-paid task service. The hidden goal remains external. PID1 pays to `Read20`, retains the successful active middle byte into the next task, searches under changed hidden goals, and self-Halts after four completed episodes or its failure budget.
5. The entire native original PID lifetime uses unchanged `World::with_strict_capacity(16,180,300)`, **172/180 source nodes, ≤16 owned data keys and ≤189/300 occupied storage units**, no PID2, restart, host rule injection or native code modification.
