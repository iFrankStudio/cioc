## Original PID1 mechanism — separate task program and durable mutation-rule data

**No native code patch or extra process:** `World::with_strict_capacity(16,180,300)`, one and only one original PID1, exact **177 authored original CIL source instructions** (maximum180), at most16 shared cell keys and **194/300 peak total occupied storage**, 4,000 initial paid private credits per world, no pool, graph object, PID2, kernel opcode modification, external program-slot edit or host-provided winner. All original worlds have byte-identical native founder source. Allowed host SetCell events: gate21 at start and probe/heldout input7; correctness feedback20 only after a **real native Write11 probe service** (absent signal means no cell20 creation). Every source step/credit and intervention is accounted.

Task program and meta rule are **different mutable memory objects**:
- The actor's **task program** lives in `cells51–54` and is dynamically fetched via actor-paid native `Read50 → Add(51+PC) → Read indirect`. Authored virtual primitives: `LOAD_INPUT=0`, `NEGATE_ACC=1`, `ADD_LITERAL2=2`, `RETURN_WRITE11=3`. Configurations A=`[0,3,3,3]` computes `x`; C=`[0,1,2,3]` computes `−x+2`; B=`[0,1,3,3]` computes `−x`. Each virtual non-return operation pays Write56 for accumulator; each actual output is Write11 in the unchanged PID1.
- The **persistent mutator rule descriptor** lives at **key63**, distinct from readonly experiment gate21, and stores R0=`0` or R1=`1`. After a current candidate *actually executes two different probe inputs* `−7` and `5`, pays Read20 twice and scores2/2 in its own cell61, a successful C candidate triggers actor-paid Write63(0), and a successful B candidate actor-paid Write63(1). Successful A leaves the rule unchanged. These are paid data writes **without any native opcode graph changes**.
- At every task phase boundary, PID1 pays to reset current program A, probe stage32, candidate index33, score61, attempted-candidate count62, virtual PC50 and bytecode slots52/53, **but retains rule63**. After subsequent A failure, its native CIL source pays `Read63` and derives its **actual NEXT program mode as rule+1**: R0 proposes C first, R1 proposes B first. PID1 then pays the two real data-program slot Writes52/53, and executes those virtual instructions; a failed C/B proposal may try the alternative.
- Frozen controls share the SAME original code: gate0 lets the actor still evaluate/execute/change real candidate programs but redirects a **rule63** write to paid **shadow Write56** and freezes its initial R0; gate2 makes the actor itself pay an initial rule63=1 write, then redirects later rule changes into paid shadow56 to freeze prespecified R1. The external host **never writes cell63**. Source and ordinary input are identical, while the gate is a disclosed environment-given control and fixed-R1 is a **privileged a priori preference baseline**.
- Cell62 is a native-paid **count of rejected two-probe candidate evaluations**. It is **not** a sensor of process private credits, which this unchanged CIL ISA does not expose. Reports of the exact charged-instruction efficiency below are from the independent evaluator (not magically known to PID1), and include actor-paid bookkeeping overhead.

When three candidates fail within a task period, the actor pays Read63 and reinstalls its rule-preferred program B/C before heldout. This is a **policy fallback**. It counts as restoring a previously validated program only if native historical records show that the same rule preference was previously earned through a genuine score2/2. An initially imposed fixed rule or manipulated success is *not* inherently a validated best program.

## 60 original worlds: two-probe feedback, transfer, adversarial counterfactual

Four hidden two-phase schedules S0=`NEGATE→NEGATE`, S1=`COMPOSED→COMPOSED`, S2=`NEGATE→COMPOSED`, S3=`NEGATE→UNREACHABLE` (where UNREACHABLE(x)=x+4 and **none** of A/B/C can match); five signal types `TRUTH`, `BLIND_SUCCESS` (fixed PRESENT bit1), `INVERTED`, `ABSENT` (no cell20 at all; VM default Read0), and `PHASE0_C_DECOY` (only the first phase C program receives falsified positive bits, all second-phase feedback truthful); three disclosed gate arms (mutable rule1, frozen-R0 0, frozen-R1 2). **4×5×3=60** original strict Rust worlds, full source and event histories.

All real probe outputs were checked against hidden task's two distinct values: A`[-7,5]`, B`[7,-5]`, C`[9,-3]`, unreachable`[-3,9]`; heldout input11 maps to `11,−11,−9,15` respectively. There is no target alias at either probe. The host gives the actor **only normal feedback bits** (not the hidden task label) and the next input value, never winning rule or program.

**Truthful source-pinned cost results** (cost measured in original PID1 native charged CIL instruction counts; each phase ends at its real heldout service):

| Hidden task schedule | Mutable rule phase-1 cost | Frozen-R0 phase-1 cost | Frozen-R1 phase-1 cost | Mutable truthful heldout |
|---|---:|---:|---:|---|
| S0 NEGATE→NEGATE | **371** | 586 | 371 | **2/2** |
| S1 COMPOSED→COMPOSED | **434** | 434 | 607 | **2/2** |
| S2 NEGATE→COMPOSED | **607** | **434** | 607 | **2/2** |
| S3 NEGATE→UNREACHABLE | 593 | 614 | 593 | **1/2** |

**S0 learning benefit:** an initially R0 PID1 spends the first period trying C and B on NEGATE, earns B's two real positive bits, pays Write63(1), then on the next matched NEGATE phase reads persistent63=1 and tries B directly after A fails. Phase-1 cost **371** versus source-identical frozen-R0's **586**; same heldout correct, **215 actual CIL steps saved** (36.7% fewer than frozen-R0) including actor-paid rule reading. Important qualification: source-identical **frozen-R1 already has the correct order without paying to learn it**, and total cost is **761** CIL steps, less than mutable training-plus-test `973`. No universal cost superiority is claimed.

**S1 transfer symmetry:** when COMPOSED is unchanged, learned/current R0 prefers C and phase1 costs434 compared with a privileged but wrong frozen-R1's607 (173 steps saved); however mutable and frozen-R0 tie because the initially authored R0 was already optimal.

**S2 negative transfer:** learning B-first for earlier NEGATE incurs **607** phase1 steps on a COMPOSED task compared with frozen-R0 **434** (173 additional actor-paid steps), although both eventually solve the heldout. Therefore **a mutable mutation rule can make adaptation slower when the environment changes**. This negative evidence remains part of the primary conclusion.

**S3 source-origin fallback failure:** after successful B in the first NEGATE period, persistent rule=R1 is actor-paid and previously validated; the next UNREACHABLE task makes A, B and C fail. Native PID1 pays a real Read63 fallback and reinstalls B. It outputs **−11 instead of the hidden target15**. The fallback mechanism is genuine but does NOT solve a new function outside the authored grammar. Frozen-R0 would instead fall back C, also incorrect; there is no de novo new opcode.

**Targeted feedback deception, strict future-choice counterfactual:** under S0 and mutable gate1, both truthful and `PHASE0_C_DECOY` worlds begin with identical source, program and first A services. Only after the real phase0 C probe does the decoy host force C's ordinary feedback bits1. The decoy incorrectly accepts C, leaves persistent rule R0, and its phase0 heldout output **−9 fails** against target−11. The truthful world instead validates B and pays a real rule63 change R0→R1. In phase1, **both worlds receive exactly the same truthful feedback on identical A outputs**, yet after A's failure the actor's next real data-bytecode writes differ:

- TRUTH remembered rule R1: `Write52(1), Write53(3)` ⇒ choose B first.
- PHASE0_C_DECOY remembered rule R0: `Write52(1), Write53(2)` ⇒ choose C first.

Decoy's second phase eventually recovers B and succeeds, but costs **586** instead of truthful learned-rule **371**, 215 extra charged CIL operations. This distinguishes **persistent feedback-dependent rule memory causation** from a merely immediate reaction to the latest feedback bit. It also demonstrates that unauthenticated feedback can poison learning.

**Crucial distinction on mutation counts:** the observer's `actor_paid_true_mutation_rule_updates=14` field counts **actor-paid Write63 events** in the enabled-rule arm, not 14 distinct changes of value. The performance comparison is based on small authored functions, two fixed probes and a two-rule mutation grammar; no long-term stochastic environmental selection, new primitive synthesis or automatic sensor of private credits exists. The test demonstrates **bounded data-encoded mutation-rule preference learning**, **repeated-task benefit**, **task-shift negative transfer**, **deception vulnerability** and **honest unsolved fallback**. It is a meaningful strictly verified engineering checkpoint, but not a demonstration of open-ended cyberlife.
